# 01. 프로젝트 개요

moai-works 가 무엇을 왜 만드는지, 누가 쓰는지, 무엇을 하고 무엇을 하지 않는지를 정한다.

**바로가기:** [배경](#1-배경) · [목표](#2-목표) · [범위](#3-범위) · [사용자](#4-사용자) · [Redmine 대응](#5-redmine-대응) · [핵심 시나리오](#6-핵심-시나리오) · [성공 지표](#7-성공-지표) · [제약 · 가정](#8-제약--가정)

## 1. 배경

- 팀은 Redmine 같은 프로젝트 관리 도구로 일감 · 일정 · 시간을 관리해 왔다. Redmine 은 기능이 넓고 단단하지만, 여러 팀 · 회사를 한 설치에서 나누어 쓰기 어렵고(워크스페이스가 없다), 화면이 오래됐고, **AI Agent 가 사람처럼 일감을 다루게 할 표준 입구가 없다.**
- AI 코딩 Agent(Claude Code 등)는 이제 일감을 읽고 · 쪼개고 · 상태를 바꾸고 · 시간을 기록하는 일을 할 수 있다. 필요한 것은 Agent 를 시스템 **안에** 넣는 것이 아니라, 바깥 Agent 가 **안전하게 붙을 입구(MCP)** 와 **사람과 같은 권한 규칙**이다.
- 이 저장소는 2026-06 에 "AI-native 그룹웨어" 명세로 시작했다. 2026-11-21 사용자 지시로 **프로젝트 관리 시스템으로 피봇**하고, 내장 AI 계층(`moai-works-ai`)을 지웠다. 계정 · 워크스페이스 · 권한 · 로그인 토대는 이미 동작하는 형제 저장소 moai-wiki 의 것을 그대로 가져왔다([ADR-001](design/00-key-decisions.md#adr-001) · [ADR-002](design/00-key-decisions.md#adr-002)).

## 2. 목표

| # | 목표 | 확인 방법 |
|---|---|---|
| G1 | Redmine 의 핵심 기능(프로젝트 · 일감 · 워크플로 · 버전 · 시간 · 위키 · 알림)을 워크스페이스 단위로 쓸 수 있다 | [요구사항](requirements/00-overview.md) M 항목의 수용 기준 |
| G2 | 바깥 AI Agent 가 MCP 로 붙어 일감을 찾고 · 만들고 · 고치고 · 메모하고 · 시간을 기록한다 | [FR-MCP](requirements/12-mcp.md) M 항목, 실제 Claude Code 연결 시험 |
| G3 | Agent 는 사람과 **같은 권한 규칙** 안에서만 움직이고, 한 일은 모두 이력 · 감사에 Agent 로 남는다 | 권한 회귀 테스트 · 감사 기록 |
| G4 | 한 설치에서 여러 팀 · 회사가 워크스페이스로 나뉘어 서로의 데이터를 볼 수 없다 | 워크스페이스 경계 테스트(다른 워크스페이스는 404) |
| G5 | Redmine 에서 옮겨 올 수 있다 | [Redmine 이관](requirements/11-integration.md) 시험 |

## 3. 범위

| 한다 | 하지 않는다 |
|---|---|
| 워크스페이스 · 계정 · 가입 · 초대 · 역할(moai-wiki 와 같은 토대) | 시스템 안의 LLM · AI 기능(요약 · 분류 · 자동 배정) — 바깥 Agent 몫 |
| 프로젝트 · 하위 프로젝트 · 모듈 · 멤버 · 프로젝트 역할 | 그룹웨어 기능(결재 · 근태 · 메신저 · 메일함) — 피봇 전 범위 |
| 일감 · 이력 · 관계 · 하위 일감 · 첨부 · 워크플로 · 사용자 정의 필드 | Redmine 플러그인 호환 |
| 질의 · 목록 · 칸반 보드 · 내보내기 | 저장소 코드 호스팅(Git 서버 자체) |
| 버전 · 로드맵 · 간트 · 캘린더 · 시간 기록 · 보고서 | 회계 · 청구(시간 기록의 비용 계산은 C) |
| 위키 · 뉴스 · 문서 · 파일 · 포럼 · 알림 · 메일 · 활동 · 검색 | 모바일 앱(반응형 웹으로 대신) |
| **MCP 엔드포인트 · MCP 키 · Agent 계정 · MCP 도구** | |
| REST API · 웹훅 · Git 웹훅 연동 · CSV 가져오기 · Redmine 이관 | |

## 6. 핵심 시나리오

| ID | 시나리오 | 흐름 |
|---|---|---|
| UC-01 | 팀이 워크스페이스를 연다 | 가입 → 시스템 관리자가 팀 워크스페이스 허용 → 팀 워크스페이스 만들기 → 멤버 초대 · 가입 승인 |
| UC-02 | 프로젝트를 만들고 일감을 관리한다 | 프로젝트 만들기 → 멤버 · 역할 → 일감 만들기 → 담당 · 상태 전이(워크플로) → 메모 · 첨부 → 닫기 |
| UC-03 | 릴리스를 계획한다 | 버전 만들기 → 일감을 버전에 담기 → 로드맵 · 간트로 진척 보기 → 버전 닫기 |
| UC-04 | 시간을 기록하고 본다 | 일감에 시간 기록 → 소요 시간 보고서(사람 · 작업 분류 · 월별) |
| UC-05 | **AI Agent 가 일감을 처리한다** | 관리자가 MCP 엔드포인트와 Agent 계정을 만들고 프로젝트 역할(개발자)을 준다 → 서비스 키를 Claude Code 에 등록 → Agent 가 `search_issues` 로 자기 담당 일감을 찾고 `get_issue` 로 읽고 · 작업 뒤 `add_issue_note` · `update_issue`(상태 · 진척률) · `log_time` → 이력에 "Agent 계정" 으로 남는다 |
| UC-06 | **사람이 자기 키로 Agent 를 쓴다** | 멤버가 개인 MCP 키를 발급 → Claude Code 에 등록 → Agent 가 그 사람의 권한으로 일감을 정리 → 이력에 "그 사람 (MCP 로)" |
| UC-07 | 커밋으로 일감을 닫는다 | Git 웹훅 → 커밋 메시지 `fixes #123` → 일감 상태 · 진척률 변경 + 커밋 연결 |
| UC-08 | Redmine 에서 옮겨 온다 | Redmine 주소 · API 키 입력 → 대응표 확인 → 가져오기 → 번호 대응표 |

## 8. 제약 · 가정

- **moai-wiki 와 같게**: 구조(`src/` 아래 모듈) · 의존성 판 · 인증(Keycloak Organizations, BFF 세션) · 역할과 권한(권한 코드 = Keycloak 클라이언트 역할, 접근 어노테이션) · 워크스페이스(개인/팀, 퍼블릭/프라이빗) — 2026-11-21 사용자 지시.
- 로컬 인프라는 다른 프로젝트와 같이 쓰는 컨테이너(MOAI-DB · MOAI-Redis · MOAI-MinIO · MOAI-OpenSearch · MOAI-Keycloak)를 쓴다. 우리 것만 다룬다.
- 메일은 SMTP 가 정해질 때까지 로그 모드다.
- 운영 배치(클라우드/사내)와 규모는 아직 정하지 않았다([정해야 할 것](wbs/08-decisions.md)).
