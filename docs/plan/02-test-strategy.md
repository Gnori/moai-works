# 테스트 전략

무엇을 어떻게 시험하고, 요구사항의 수용 기준을 언제 "확인함"으로 체크하는지 정한다. moai-wiki 와 같은 층 · 같은 규칙이다 — 위키 경계 시험이 프로젝트 경계 시험으로, 페이지 시험이 일감 시험으로 바뀐다.

**바로가기:** [층](#ts-layers) · [꼭 있어야 하는 시험](#ts-must) · [MCP 시험](#ts-mcp) · [수용 기준 체크](#ts-acceptance) · [데이터](#ts-data)

<a id="ts-must"></a>
## 2. 꼭 있어야 하는 시험

새 엔드포인트 · 권한 규칙을 만들면 **같은 작업에서** 아래를 더한다(moai-wiki 와 같은 규칙). 권한이 걸린 엔드포인트는 적어도 경계 404 · 권한 없음 403 · 허용 200 을 넣는다.

| 종류 | 확인 |
|---|---|
| 워크스페이스 경계 | 다른 워크스페이스의 멤버 · 비멤버가 부르면 404 `WORKSPACE_NOT_FOUND`(없는 것과 남의 것을 구별할 수 없음) |
| 프로젝트 경계 | 독자가 아니면 404 `PROJECT_NOT_FOUND` — `RESTRICTED` 프로젝트에 역할이 없는 멤버 · 없는 프로젝트 · 관리 권한 없이 보관된 프로젝트를 구별할 수 없다. 독자인데 그 코드가 없으면 403 `PERMISSION_REQUIRED`. 없는 일감 · 다른 프로젝트의 일감 번호는 404 `ISSUE_NOT_FOUND`. 목록에도 독자인 프로젝트만 나온다 |
| 권한 합과 반영 | 프로젝트 권한 = 워크스페이스 역할 ∪ 프로젝트 역할. 기본 역할 넷(소유자 · 관리자 · 큐레이터 · 멤버)과 프로젝트 역할 넷이 설계대로. 역할을 주고 빼면 다음 요청부터 반영 |
| 권한 상승 | 자기 권한 밖의 워크스페이스 역할 · 프로젝트 역할 · 코드를 줄 수 없음(403 `ESCALATION_DENIED`). 일감 관리자를 바꾸려면 `issue.manager.assign` 도 있어야 함 |
| 낙관적 잠금 | 옛 `rowVersion` 으로 고치면 409 `CONCURRENT_UPDATE`, 값은 바뀌지 않음 |
| 일감 규칙 | 날짜 검사 · 상태에 따른 완료일 · 종료일 채움과 비움 · 상위 순환 · 깊이 10 · 다른 프로젝트의 상위 · 연결 거절 · 같은 두 일감의 두 번째 연결 거절 · 하위가 있는 일감 지우기 거절 · 관리자 · 담당자는 그 프로젝트의 독자인 활성 멤버만 · 번호가 동시에 만들어도 겹치지 않음 |
| 이력 · 감사 | 일감을 고칠 때마다 이력 한 줄(바뀐 필드 전 · 후), 프로젝트 · 역할 · 일감 지우기 · MCP 키는 감사에 남고, 행위자(사람 `USER` · 서비스 키 `SERVICE`) · 경로(`WEB` · `MCP`)가 맞음 |
| Keycloak 정본 | 프로젝트 역할의 Keycloak 조직 그룹(`/projects/<id>/<role>`)과 DB 사본(`project_role_binding`)이 같다(`FakeKeycloak`) |

<a id="ts-mcp"></a>
## 3. MCP 시험

| 종류 | 확인 | 어떻게 |
|---|---|---|
| 동등성 | 같은 주체가 같은 일을 웹(REST)과 MCP 도구로 했을 때 결과 · 판정 · 이력이 같다(via 만 다름) | api 자동 테스트에서 MCP 서버를 직접 부른다(서비스 계층 같은 길) |
| 범위 | 엔드포인트 대상 밖의 프로젝트 · 끈 도구 · 꺼진 엔드포인트 · 다른 엔드포인트의 키 · `QUERY` 엔드포인트의 쓰기 · 서비스 키 `SERVICE` 읽기 모드의 `RESTRICTED` 프로젝트는 거절. 모델이 넘긴 프로젝트 · 일감 값으로 범위가 넓어지지 않는다 | 자동 테스트 |
| 키 | 폐기 · 만료 · 멤버가 나간(정지된) 개인 키는 거절. 키 발급은 워크스페이스에 묶이고 권한 · 감사가 있다(비멤버 404 · 권한 없음 403) | 자동 테스트 |
| 재판정 | 호출 사이에 프로젝트 역할 · 워크스페이스 역할을 빼면 다음 도구 호출부터 거절(MCP 세션을 열었다고 건너뛰지 않음) | 자동 테스트 |
| 안전장치 | 멱등 키로 같은 요청 두 번 → 한 번만 처리, 속도 제한, 응답 크기 상한, MCP 로 열지 않는 일(지우기 · 설정 · 역할)은 도구가 없음 | 자동 테스트 |
| 실물 | Claude Code 로 붙여 `tools/list` → 시나리오 UC-05 · UC-06([개요 §6](../01-overview.md#6-핵심-시나리오)) | 사람이 띄워서 |

<a id="ts-acceptance"></a>
## 4. 수용 기준 체크

- 요구사항의 수용 기준은 **자동 테스트나 실제 화면 · 흐름으로 확인한 것만** `- [x]` 로 바꾼다([요구사항 개요 §6](../requirements/00-overview.md#6-진행-관리)).
- 토대(FR-WSP)는 moai-wiki 에서 확인한 코드지만, moai-works 에서는 자동 테스트가 다루는 기준과 2026-11-22 로그인 흐름만 체크했다. 나머지는 moai-works 렐름에서 실제 흐름으로 확인한 뒤 체크한다.
- 실패한 검사는 실패라고, 건너뛴 검사는 건너뛰었다고 적는다.
