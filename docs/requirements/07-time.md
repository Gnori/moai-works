# 시간 기록 요구사항 (FR-TIM)

일감이나 프로젝트에 들인 시간을 기록하고, 목록 · 보고서로 모아 보고, 예상과 견주는 기능의 요구사항이다. Redmine 의 시간 기록(날짜 · 시간 · 작업 분류 · 메모 · 남 대신 기록)과 소요 시간 보고서를 따른다. 설계는 [계획 · 시간 설계](../design/06-planning-time.md#pt-time)에 있다.

| 공통 | 내용 |
|---|---|
| 권한 검사 | api 가 요청마다 판정한다. 프로젝트 독자가 아니거나 `time_tracking` 모듈이 꺼져 있으면 404, 권한 코드가 없으면 403([프로젝트 요구사항](02-project.md)). 닫힌 프로젝트의 쓰기는 409 `PROJECT_READ_ONLY` |
| 권한 코드 | 보기 · 보고서 `time.read` · 기록 `time.log` · 내 기록 고치기 `time.edit.own` · 모든 기록 고치기와 남 대신 기록 `time.edit.all` |
| 시간은 사람의 것 | "누구의 시간"은 사람 멤버만. Agent 계정은 사람 대신 기록하는 "기록한 사람"이 될 수 있다(자기 시간은 남기지 않는다) |
| 감사 | 시간 기록의 만들기 · 고치기 · 지우기는 감사에 전후 값 · 행위자(사람 · Agent 계정) · 경로(웹 · REST · MCP + 키 id)를 남긴다 |
| MCP 동등성 | `log_time` · `list_time_entries` 는 REST 와 같은 서비스 · 같은 판정을 부른다([MCP 요구사항](12-mcp.md)) |
| 질의 | 시간 기록 목록 · 보고서의 거르기는 질의 엔진을 쓴다([질의 요구사항](05-query.md)) |

<a id="fr-tim-001"></a>
### FR-TIM-001 시간 기록하기

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.1](../design/06-planning-time.md#pt-time) · [§8.2](../design/06-planning-time.md#pt-time-where) |

**설명** — 일감 또는 프로젝트에 들인 시간을 날짜 · 시간 · 작업 분류 · 메모로 기록한다. 일감 없이 회의 · 지원 같은 프로젝트 시간도 기록한다.

**세부 요구사항**
1. 시스템은 `time.log` 를 가진 사람이 일감 또는 프로젝트에 시간을 기록하게 해야 한다.
2. 필드는 날짜(필수) · 시간(필수) · 작업 분류(필수, 그 프로젝트에서 켜진 것) · 메모(1024자) · 시간 기록 대상 사용자 정의 필드여야 한다.
3. 일감에 기록하면 프로젝트는 그 일감의 프로젝트여야 하고, 기록하는 사람이 그 일감을 읽을 수 있어야 한다.
4. "기록한 사람"과 경로(웹 · REST · MCP · 메일 · 커밋)를 함께 저장해야 한다.
5. 일감 쪽에 그 일감의 소요 시간과 하위 포함 합계를 보여야 한다(`time.read` 일 때).

**수용 기준**
- [ ] 일감에 2시간을 기록하면 일감 쪽의 소요 시간이 2 늘어난다
- [ ] 다른 프로젝트 id 를 넣어도 기록의 프로젝트는 일감의 프로젝트다
- [ ] `time.log` 없이 기록하면 403, 읽을 수 없는 일감에 기록하면 404 다
- [ ] 기록이 감사에 행위자 · 경로와 함께 남는다

<a id="fr-tim-002"></a>
### FR-TIM-002 시간 입력 형식

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.4](../design/06-planning-time.md#pt-time-input) |

**설명** — 사람마다 시간을 치는 버릇이 다르다. Redmine 처럼 `1.5` · `1:30` · `1h30m` 을 모두 받고, 한국어 `1시간 30분` 도 받는다. 저장은 정수 분이다.

**세부 요구사항**
1. `1.5` · `1,5` · `1:30` · `1h30m` · `1h 30m` · `2h` · `2` · `45m` · `1시간 30분` 을 받아 분으로 바꿔야 한다.
2. 0 이하(설정이 0 을 허용하지 않을 때) · 24 시간 초과 · `1:75` 같은 잘못된 값은 422 와 이유를 돌려줘야 한다. Redmine 에서 가져오는 옛 기록만 1000 시간 미만까지 받는다.
3. 저장은 정수 분이고, 응답은 `hours`(소수)와 `minutes` 둘 다여야 한다.
4. 표시는 워크스페이스 설정 · 사용자 설정에 따라 `1.50` 또는 `1:30` 이어야 한다.

**수용 기준**
- [ ] 설계 표의 모든 입력이 표의 분 값이 된다
- [ ] 잘못된 입력은 저장되지 않고 422 다
- [ ] 1:20 을 세 번 기록하면 합계가 정확히 4:00(240분)이다

<a id="fr-tim-003"></a>
### FR-TIM-003 일감 고치면서 시간 기록

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.2](../design/06-planning-time.md#pt-time-where) |

**설명** — Redmine 처럼 일감 고치기 화면에서 상태 바꾸기 · 메모와 함께 시간을 기록한다. 한 번에 저장되어야 한다.

**세부 요구사항**
1. 일감 고치기 화면에 시간 · 작업 분류 · 메모 칸을 두어야 한다(`time.log` 가 있을 때만).
2. 일감 변경과 시간 기록은 한 트랜잭션이어야 한다. 하나가 실패하면 둘 다 저장되지 않아야 한다.
3. 시간 칸을 비우면 시간 기록 없이 일감만 저장되어야 한다.

**수용 기준**
- [ ] 상태 변경 + 1시간 기록을 한 번에 저장하면 이력 한 줄과 기록 하나가 생긴다
- [ ] 시간 형식이 틀리면 일감 변경도 저장되지 않는다

<a id="fr-tim-004"></a>
### FR-TIM-004 남 대신 기록

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.5](../design/06-planning-time.md#pt-time-others) |

**설명** — 관리자가 회의 시간을 참석자 대신 기록하거나 종이 기록을 옮겨 적는다(Redmine 4.1 의 "다른 사용자의 시간 기록"). 첫 출시는 `time.edit.all` 로 판정한다.

**세부 요구사항**
1. `time.edit.all` 을 가진 사람이 "누구의 시간"을 다른 사람으로 고를 수 있어야 한다.
2. 고른 사람은 그 프로젝트에서 `time.log` 를 가진 사람 멤버여야 한다. Agent 계정은 고를 수 없어야 한다.
3. 목록 · 보고서에 "누구의 시간"과 "기록한 사람"이 다르면 둘 다 보여야 한다.
4. Agent 계정(서비스 키)이 기록할 때는 "누구의 시간"(사람)을 꼭 정해야 하고, 그러려면 Agent 계정에 `time.edit.all` 이 있어야 한다.

**수용 기준**
- [ ] `time.edit.all` 없이 다른 사람을 고르면 403 이다
- [ ] `time.log` 가 없는 사람을 고르면 422 다
- [ ] 관리자가 대신 기록한 항목에 "관리자 Y 가 기록"이 보인다
- [ ] Agent 계정이 자기 자신의 시간을 기록하려 하면 거절된다

<a id="fr-tim-005"></a>
### FR-TIM-005 기록 고치기 · 지우기

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §2](../design/06-planning-time.md#pt-permissions) · [§11.2 SQL](../design/06-planning-time.md#pt-ddl) |

**설명** — 잘못 적은 시간을 고치거나 지운다. 자기 기록은 `time.edit.own`, 모든 기록은 `time.edit.all` 로 한다. Redmine 은 시간 기록 이력을 두지 않지만 여기서는 감사에 전후 값을 남긴다.

**세부 요구사항**
1. "누구의 시간"이 나인 기록은 `time.edit.own` 으로, 남의 기록은 `time.edit.all` 로 고치고 지울 수 있어야 한다.
2. 다른 일감으로 옮기려면 옮길 일감을 읽을 수 있고 그 프로젝트에서도 같은 권한이 있어야 한다.
3. 고치기는 낙관적 잠금(`row_version`)을 지켜야 한다.
4. 고치기 · 지우기는 감사에 전후 값을 남겨야 한다.

**수용 기준**
- [ ] `time.edit.own` 만 가진 사람이 남의 기록을 고치면 403 이다
- [ ] 고친 기록의 전후 값이 감사에 남는다
- [ ] 옛 `row_version` 으로 고치면 409 다

<a id="fr-tim-006"></a>
### FR-TIM-006 프로젝트별 작업 분류

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.6](../design/06-planning-time.md#pt-activity-enum) |

**설명** — 작업 분류(설계 · 개발 · 회의 …) 목록은 워크스페이스 열거형이다([워크플로 요구사항](04-workflow.md)). 프로젝트마다 쓸 분류만 켜고 끈다(Redmine 의 프로젝트별 작업 분류).

**세부 요구사항**
1. `project.manage` 를 가진 사람이 프로젝트 설정에서 분류마다 켜고 끌 수 있어야 한다. 덮어쓰지 않은 분류는 워크스페이스 값을 따른다.
2. 꺼진 분류로는 새 기록을 만들 수 없어야 한다. 이미 있는 기록은 그대로 보이고, 분류를 바꾸지 않는 고치기는 저장되어야 한다.
3. 기본 분류가 그 프로젝트에서 켜져 있으면 새 기록에 미리 골라 둬야 한다.

**수용 기준**
- [ ] 프로젝트에서 "회의"를 끄면 그 프로젝트 기록 화면 · `log_time` 에서 "회의"를 쓸 수 없다
- [ ] 끄기 전에 만든 "회의" 기록은 목록에 그대로 보인다
- [ ] 설정 바꾸기가 감사에 남는다

<a id="fr-tim-007"></a>
### FR-TIM-007 기록 규칙 설정

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.3](../design/06-planning-time.md#pt-time-rules) |

**설명** — 워크스페이스마다 기록 규칙을 정한다. Redmine 의 필수 필드 · 0 시간 허용 · 미래 날짜 허용 · 하루 최대 시간 설정과 같다.

**세부 요구사항**
1. `config.manage` 를 가진 사람이 필수 필드(일감 · 메모) · 0 시간 허용 · 미래 날짜 허용 · 하루 최대 시간 · 닫힌 일감 기록 허용 · 표시 형식을 정할 수 있어야 한다.
2. 모든 경로(웹 · REST · MCP · 메일 · 커밋 · 가져오기)의 기록이 같은 규칙으로 검사되어야 한다. 가져오기는 예외로 둘 수 있다(옮겨 오는 옛 기록).
3. 하루 최대 시간은 그 사람 · 그 날짜의 기존 합 + 새 값으로 검사해야 한다.

**수용 기준**
- [ ] 메모 필수를 켜면 메모 없는 `log_time` 이 거절된다
- [ ] 하루 8시간 상한에서 6시간 기록 뒤 3시간 기록은 422 다
- [ ] 미래 날짜 금지를 켜면 내일 날짜 기록이 422 다

<a id="fr-tim-008"></a>
### FR-TIM-008 시간 기록 목록 · CSV

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.8](../design/06-planning-time.md#pt-time-list) |

**설명** — 프로젝트 · 워크스페이스의 시간 기록을 거르고 묶고 합계 내어 본다. 질의처럼 저장하고 CSV 로 내보낸다.

**세부 요구사항**
1. 거르기: 날짜(오늘 · 이번 주 · 지난 달 · 기간 …) · 누구의 시간 · 기록한 사람(사람 · Agent) · 작업 분류 · 프로젝트(하위 포함) · 일감(하위 포함) · 일감의 트래커 · 상태 · 대상 버전 · 카테고리 · 메모 · 시간 · 사용자 정의 필드여야 한다.
2. 열 고르기 · 정렬 · 묶기 · 시간 합계가 있어야 한다.
3. CSV(UTF-8 BOM)로 내보낼 수 있어야 한다.
4. 비공개 일감에 붙은 기록은 그 일감을 볼 수 없는 사람에게 일감 칸과 메모를 가리고 시간 수만 보여야 한다.
5. 워크스페이스 전체 목록은 `time.read` 가 있고 모듈이 켜진 프로젝트의 기록만 보여야 한다.

**수용 기준**
- [ ] "지난 주 · 나 · 개발" 거르기 합계가 기록 합과 같다
- [ ] CSV 의 합계 줄이 화면 합계와 같다
- [ ] 비공개 일감을 못 보는 사람에게 그 일감 제목이 응답에 없다
- [ ] `time.read` 가 없는 프로젝트 기록은 워크스페이스 목록에 없다

<a id="fr-tim-009"></a>
### FR-TIM-009 예상 대 실적

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §9.4](../design/06-planning-time.md#pt-estimate) |

**설명** — 예상 시간과 실제 소요 시간을 일감 · 버전 · 프로젝트 단위로 견준다. 남은 예상 시간(예상 × 남은 진척)도 보인다(Redmine 5.1 과 같다).

**세부 요구사항**
1. 일감 쪽 · 목록 열에 예상 · 합계 예상 · 소요 · 합계 소요 · 남은 예상을 보여야 한다.
2. 버전 쪽에 예상 합계(잎 일감)와 소요 합계를 보여야 한다.
3. 프로젝트 개요에 그 프로젝트(+ 하위)의 소요 합계를 보여야 한다.
4. 소요 값은 `time.read` 가 있을 때만 보여야 한다.

**수용 기준**
- [ ] 예상 10 · 진척 40% 일감의 남은 예상이 6 이다
- [ ] 하위 일감에 기록한 시간이 상위의 합계 소요에 더해진다
- [ ] `time.read` 가 없는 사람의 일감 응답에 소요 값이 없다

<a id="fr-tim-010"></a>
### FR-TIM-010 소요 시간 보고서

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §9](../design/06-planning-time.md#pt-report) |

**설명** — 사람 · 작업 분류 · 일감 · 트래커 · 버전 · 카테고리 · 사용자 정의 필드를 행으로, 일 · 주 · 월 · 년을 열로 시간을 모은다(Redmine 소요 시간 보고서).

**세부 요구사항**
1. 행 기준을 1~3개 골라 중첩할 수 있어야 한다: 프로젝트 · 사용자 · 기록한 사람(사람 · Agent) · 작업 분류 · 일감 · 트래커 · 상태 · 버전 · 카테고리 · 사용자 정의 필드(목록 · 키-값 목록 · 사용자 · 버전 · 예/아니요 · 문자 형식).
2. 열은 일 · 주(ISO 주) · 월 · 년 중 하나이고, 행 · 열 · 전체 합계가 있어야 한다.
3. 트래커 · 상태 · 버전 · 카테고리는 일감의 지금 값으로 묶어야 한다.
4. 거르기는 시간 기록 목록과 같고, 보고서 설정을 질의로 저장할 수 있어야 한다.
5. CSV 로 내보낼 수 있어야 한다.
6. 행 조합 2,000개 · 열 366개를 넘으면 단위를 키우라고 알려야 한다.

**수용 기준**
- [ ] 다중 값 필드가 없을 때 칸 합 = 행 합 = 전체 합이다
- [ ] 2026-12-31 기록이 주 단위에서 2026-W53 에 들어간다
- [ ] CSV 의 칸 값이 화면과 같다
- [ ] `time.read` 가 없는 프로젝트의 시간이 보고서에 섞이지 않는다

<a id="fr-tim-011"></a>
### FR-TIM-011 일감 옮기기 · 지우기와 시간 기록

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.7](../design/06-planning-time.md#pt-time-issue) |

**설명** — 일감을 다른 프로젝트로 옮기면 시간 기록도 따라간다. 시간 기록이 붙은 일감을 지울 때는 기록을 어떻게 할지 고른다(Redmine 과 같다).

**세부 요구사항**
1. 일감을 옮기면 그 일감 시간 기록의 프로젝트를 같은 트랜잭션에서 바꿔야 한다.
2. 시간 기록이 붙은 일감을 지울 때 "기록도 지우기" · "프로젝트에 남기기"(기본) · "다른 일감으로 옮기기" 중 고르게 해야 한다.
3. "기록도 지우기"는 지우는 사람이 그 기록들을 고칠 수 있을 때만, "다른 일감으로"는 대상 일감을 읽을 수 있고 그 프로젝트에서 고칠 수 있을 때만 골라져야 한다.

**수용 기준**
- [ ] 일감을 옮긴 뒤 그 기록이 새 프로젝트 목록에 나온다
- [ ] "프로젝트에 남기기"로 지우면 기록의 일감 칸이 비고 프로젝트 합계는 그대로다
- [ ] 권한 없이 "기록도 지우기"를 고르면 403 이고 일감도 지워지지 않는다

<a id="fr-tim-012"></a>
### FR-TIM-012 MCP 로 시간 기록 · 보기

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §13](../design/06-planning-time.md#pt-mcp) |

**설명** — 바깥 Agent 가 "이 일감에 1시간 30분 기록해 줘"를 하거나 이번 주 기록을 모아 볼 수 있게 MCP 도구를 연다.

**세부 요구사항**
1. `log_time` 은 일감 번호 또는 프로젝트, `hours`(0 초과 24 이하) 또는 `duration`("1:30"), 날짜(기본 오늘, 워크스페이스 시간대), 작업 분류(이름 · id, 기본 분류), 메모, `user`(남 대신, 선택), `idempotency_key`(필수)를 받아야 한다.
2. 검사(형식 · 규칙 · 권한)는 웹과 같아야 하고, 같은 멱등 키는 24시간 같은 결과를 돌려줘야 한다.
3. 서비스 키(Agent 계정)로 `user` 를 비우면 거절해야 한다(Agent 자신의 시간은 받지 않는다).
4. `list_time_entries` 는 프로젝트 또는 일감 · 기간 · 사람 · 작업 분류 · 커서 · 개수를 받아 목록과 합계를 돌려줘야 한다.
5. 기록에는 경로 MCP · 키 id 가 남고, 화면에 "김가 (MCP 로)" · "Agent X 가 기록"으로 보여야 한다.

**수용 기준**
- [ ] `log_time(duration="1:30")` 이 90분 기록을 만들고 일감 합계를 돌려준다
- [ ] 같은 멱등 키로 두 번 부르면 기록이 하나다
- [ ] 엔드포인트 대상이 아닌 프로젝트에 기록하면 거절된다
- [ ] 서비스 키로 `user` 없이 부르면 거절되고, `user` 를 정하면 그 사람의 시간에 "Agent X 가 기록"이 남는다
- [ ] 감사에 MCP 엔드포인트 · 키 id 가 남는다

<a id="fr-tim-013"></a>
### FR-TIM-013 시간 기록 마감

| 항목 | 내용 |
|---|---|
| 우선순위 | C |
| 진행 | 할 일 |
| 관련 설계 | [계획 설계 §8.3](../design/06-planning-time.md#pt-time-rules) |

**설명** — 정산이 끝난 달의 기록을 잠근다. Redmine 은 플러그인으로 하는 일이다.

**세부 요구사항**
1. `config.manage` 를 가진 사람이 "이 날짜 이전 기록 잠금" 날짜를 정할 수 있어야 한다.
2. 잠긴 기간의 기록은 만들기 · 고치기 · 지우기가 모든 경로에서 막혀야 한다.

**수용 기준**
- [ ] 마감일 이전 날짜로 기록하거나 고치면 422 다
- [ ] 마감일 바꾸기가 감사에 남는다
