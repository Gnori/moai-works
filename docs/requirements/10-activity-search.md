# 활동 · 검색 · 내 페이지 요구사항 (FR-ACT)

일어난 일을 시간순으로 되짚는 활동(프로젝트 · 사람 · 전체), 일감 · 메모 · 위키 · 뉴스 · 문서 · 포럼을 한 번에 찾는 검색(OpenSearch nori), 사람마다 블록을 골라 꾸미는 내 페이지의 요구사항이다. Redmine 의 활동(종류 거르기 · Atom) · 검색(대상별, `#123` 이면 바로 이동) · 내 페이지(블록)를 따른다. 설계는 [공동 작업 설계 §11 ~ §13](../design/08-collaboration.md#co-activity)에 있다.

| 공통 | 내용 |
|---|---|
| 보는 사람 기준 | 활동 · 검색 결과 · 내 페이지 블록은 보는 사람이 지금 읽을 수 있는 것만 보인다(프로젝트 독자 · 모듈 켜짐 · 읽기 코드 · 비공개 일감 · 비공개 메모 규칙) |
| 권한 검사 | api 가 요청마다 판정한다. 읽을 수 있는 프로젝트 목록을 api 가 계산해 질의(SQL · OpenSearch)에 넣는다. 화면은 숨기기만 한다([프로젝트 요구사항](02-project.md)) |
| 행위자 | 사람 · Agent 계정 · "사람 (MCP 로)" · "사람 (메일로)" 를 구별해 보이고 거른다 |
| 검색 엔진 | OpenSearch 3.9(nori), 색인 `moai-works-*`. 정본은 PostgreSQL 이고 색인은 다시 만들 수 있다 |
| MCP 동등성 | `get_activity` 는 REST 와 같은 서비스 · 같은 판정을 부른다([MCP 요구사항](12-mcp.md)) |
| 감사 | 내 페이지 배치 저장은 감사에 남기지 않는다(개인 화면 설정). 색인 다시 만들기 같은 운영 작업은 감사에 남긴다 |

<a id="fr-act-001"></a>
### FR-ACT-001 프로젝트 활동

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §11](../design/08-collaboration.md#co-activity) · [§11.3](../design/08-collaboration.md#co-activity-filter) |

**설명** — 프로젝트에서 일어난 일(일감 · 메모 · 위키 편집 · 뉴스 · 문서 · 파일 · 글 · 변경 묶음 · 소요 시간)을 날짜별로 본다. Redmine 활동과 같다.

**세부 요구사항**
1. 종류는 일감 · 변경 묶음 · 뉴스 · 문서 · 파일 · 위키 편집 · 게시판 글 · 소요 시간이어야 하고, 소요 시간은 기본으로 숨겨야 한다.
2. 일감은 만들기 · 메모 · 상태 변경이 있는 변경만 활동에 넣어야 한다.
3. 기본 기간은 30일(워크스페이스 설정)이고 "이전"으로 그 앞 기간을 보며, 날짜별로 묶어야 한다.
4. "하위 프로젝트 포함"을 고를 수 있어야 한다.
5. 활동은 이벤트를 낸 트랜잭션에서 바로 기록되어야 한다. 일감을 옮기면 활동도 따라가고, 대상이 지워지면 활동도 지워져야 한다.
6. 원본에서 활동을 다시 만드는 운영 작업이 있어야 한다.

**수용 기준**
- [ ] 일감에 메모를 달면 바로 프로젝트 활동에 나온다
- [ ] 소요 시간은 기본으로 안 보이고, 켜면 `time.read` 가 있을 때만 보인다
- [ ] 비공개로 바꾼 일감의 활동이 권한 없는 사람에게 바로 안 보인다
- [ ] 독자가 아닌 프로젝트의 활동은 404, 모듈이 꺼진 종류는 나오지 않는다

<a id="fr-act-002"></a>
### FR-ACT-002 워크스페이스 전체 활동

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §11.3](../design/08-collaboration.md#co-activity-filter) |

**설명** — 내가 읽을 수 있는 모든 프로젝트의 활동을 한 줄로 본다.

**세부 요구사항**
1. 읽을 수 있고 해당 모듈이 켜진 프로젝트의 활동만 보여야 한다.
2. 항목마다 프로젝트 이름을 보여야 한다.
3. 거르기(종류 · 행위자 종류 · 경로 · 기간)는 프로젝트 활동과 같아야 한다.
4. 프로젝트 수천 개 · 활동 수백만 건에서도 한 쪽을 1초 안에 줘야 한다.

**수용 기준**
- [ ] 독자가 아닌 RESTRICTED 프로젝트 활동이 나오지 않는다
- [ ] 한 쪽 응답이 시험 데이터(활동 100만 건)에서 1초 안이다

<a id="fr-act-003"></a>
### FR-ACT-003 사람 쪽 · 사람별 활동

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §11.3](../design/08-collaboration.md#co-activity-filter) |

**설명** — 사람(또는 Agent 계정) 쪽에서 그 주체의 활동을 본다. Redmine 사용자 쪽과 같다.

**세부 요구사항**
1. 사람 쪽에 표시 이름 · 함께 속한 프로젝트와 역할 · 보고한 일감 수 · 최근 활동을 보여야 한다. 메일 주소는 보이지 않아야 한다.
2. Agent 계정 쪽에도 같은 모양으로 그 Agent 의 활동과 책임자를 보여야 한다.
3. 그 주체의 활동 중 **보는 사람이** 읽을 수 있는 것만 보여야 한다.

**수용 기준**
- [ ] 내가 못 읽는 프로젝트에서의 그 사람 활동이 나오지 않는다
- [ ] Agent 계정 쪽에 그 Agent 가 MCP 로 한 변경이 나온다

<a id="fr-act-004"></a>
### FR-ACT-004 활동 Atom 피드

| 항목 | 내용 |
|---|---|
| 우선순위 | C |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §11.5](../design/08-collaboration.md#co-atom) |

**설명** — 피드 리더로 활동을 구독한다(Redmine 의 Atom). 피드 리더는 로그인 세션이 없으므로 사람마다 읽기 전용 피드 키를 쓴다.

**세부 요구사항**
1. 프로젝트 · 워크스페이스 활동을 Atom 으로 내줘야 한다. 거르기는 화면과 같다.
2. 피드 키는 사람마다 하나, 원문은 한 번만 보이고 SHA-256 만 저장하며, 다시 발급하면 옛 키가 무효여야 한다.
3. 피드는 키 주인의 권한으로 걸러야 한다.

**수용 기준**
- [ ] 다시 발급한 뒤 옛 키로 피드를 열면 401 이다
- [ ] 피드에 키 주인이 못 읽는 항목이 없다

<a id="fr-act-005"></a>
### FR-ACT-005 행위자 표시 · 거르기

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §11.4](../design/08-collaboration.md#co-actor) |

**설명** — 사람과 바깥 Agent 가 함께 일하므로, 누가(사람 · Agent 계정) 어디로(웹 · MCP · 메일 · 커밋) 했는지가 활동마다 보여야 한다.

**세부 요구사항**
1. 활동마다 행위자를 "김가" · "김가 (MCP 로)" · "Agent 빌드봇" · "김가 (메일로)" 꼴로 보여야 한다. MCP 는 엔드포인트 이름을 덧붙여 볼 수 있어야 한다.
2. 행위자 종류(사람 · Agent · 모두)와 경로(웹 · MCP · 메일 · 커밋)로 거를 수 있어야 한다.
3. 같은 표시가 활동 · 일감 이력 · 위키 판 · 알림에서 같아야 한다.

**수용 기준**
- [ ] 개인 MCP 키로 고친 일감의 활동에 "(MCP 로)" 가 보인다
- [ ] "Agent 만" 거르기에서 사람 활동이 나오지 않는다

<a id="fr-act-006"></a>
### FR-ACT-006 통합 검색

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §12.1](../design/08-collaboration.md#co-search-targets) · [§12.2](../design/08-collaboration.md#co-search-mapping) · [§12.4](../design/08-collaboration.md#co-search-query) |

**설명** — 일감 · 메모 · 위키 · 뉴스 · 문서 · 파일 · 게시판 글 · 프로젝트 · 변경 묶음을 한 번에 찾는다. 한국어는 nori 형태소 분석을 쓴다. Redmine 검색의 선택(모든 낱말 · 제목만 · 열린 일감만 · 대상 고르기 · 범위)을 둔다.

**세부 요구사항**
1. 범위는 이 프로젝트 · 하위 포함 · 내 프로젝트 · 워크스페이스 전체여야 한다.
2. 대상 종류를 고를 수 있고, 결과 위에 종류별 개수를 보여야 한다.
3. 선택: 모든 낱말(기본) / 낱말 하나라도, 제목만, 열린 일감만, 따옴표 구절.
4. 결과는 점수순이고 항목마다 종류 · 제목 · 강조한 조각 · 프로젝트 · 시각 · 주소를 보여야 한다. 강조 조각은 HTML 을 이스케이프하고 강조 표시만 넣어야 한다.
5. 영문 · 코드 낱말(`NullPointerException`, `v1.2.3`)도 찾아야 한다.
6. OpenSearch 가 안 되면 "검색을 잠시 쓸 수 없다"(503)를 보여야 한다.

**수용 기준**
- [ ] "로그인 오류" 로 "로그인할 때 오류가 났다" 일감이 찾아진다(형태소)
- [ ] "제목만" 이면 본문에만 낱말이 있는 일감이 빠진다
- [ ] "열린 일감만" 이면 닫힌 일감이 빠진다
- [ ] 강조 조각에 본문 속 HTML 태그가 실행 가능한 꼴로 들어가지 않는다

<a id="fr-act-007"></a>
### FR-ACT-007 `#123` 바로 가기

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §12.5](../design/08-collaboration.md#co-search-jump) |

**설명** — 검색 상자에 `#123` 이나 `123` 을 치면 그 일감으로 바로 간다(Redmine 과 같다).

**세부 요구사항**
1. 질의가 `#숫자` 또는 숫자뿐이고 그 번호의 일감을 읽을 수 있으면 바로 그 일감으로 가야 한다.
2. 없거나 읽을 수 없으면 보통 검색을 해야 하고, 둘을 구별해 알리지 않아야 한다.
3. 바로 가기는 OpenSearch 없이 DB 로 해야 한다(검색 엔진이 내려가도 된다).
4. 위쪽 바의 빠른 찾기 상자도 같은 동작이어야 한다.

**수용 기준**
- [ ] `#123` 을 치면 일감 #123 쪽이 열린다
- [ ] 못 읽는 일감 번호를 치면 보통 검색 결과가 나오고 그 일감은 없다
- [ ] OpenSearch 를 멈춰도 `#123` 바로 가기가 된다

<a id="fr-act-008"></a>
### FR-ACT-008 검색 권한 필터

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §12.4](../design/08-collaboration.md#co-search-query) |

**설명** — 검색은 내용이 새는 가장 쉬운 길이다. api 가 종류마다 읽을 수 있는 프로젝트 목록과 비공개 규칙을 질의의 거르기로 넣고, 돌려줄 결과를 DB 로 한 번 더 확인한다.

**세부 요구사항**
1. api 가 종류마다 읽을 수 있는 프로젝트 목록(독자 ∧ 모듈 ∧ 읽기 코드)을 계산해 질의 거르기에 넣어야 한다.
2. 일감 보기 범위(전체 · 기본 · 내 것만 — 비공개 일감은 작성자 · 담당자 · `issue.private.read`, 프로젝트 설정이 "내 것만"이면 자기 일감만)와 비공개 메모(`issue.note.private`) 규칙을 질의에 넣어야 한다. 메모 문서는 일감의 보기 범위도 함께 따라야 한다.
3. 모듈 켜고 끄기 · 공개 범위 · 멤버 · 역할이 바뀌어도 다시 색인하지 않고 바로 반영되어야 한다(질의 때 계산).
4. 돌려줄 결과를 DB 에서 한 번 더 읽어 지금도 읽을 수 있는지 확인해야 한다(색인이 늦은 사이 새지 않게).
5. MCP 로 부를 때도 같은 계산(Agent 계정의 역할 ∩ 엔드포인트 대상 프로젝트)이어야 한다.

**수용 기준**
- [ ] 프로젝트에서 빠진 사람의 검색에 그 프로젝트 결과가 바로 없어진다
- [ ] 비공개 메모 낱말로 찾아도 권한 없는 사람에게 그 메모가 나오지 않는다
- [ ] 일감을 비공개로 바꾼 직후(색인 전)에도 권한 없는 사람에게 결과가 나오지 않는다
- [ ] 위키 모듈을 끄면 그 프로젝트 위키 결과가 바로 없어진다

<a id="fr-act-009"></a>
### FR-ACT-009 색인 갱신 · 다시 만들기

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §12.3](../design/08-collaboration.md#co-search-index) |

**설명** — 쓰기 이벤트가 작업 큐를 거쳐 OpenSearch 색인을 고친다. 색인은 정본이 아니므로 언제든 DB 에서 다시 만든다.

**세부 요구사항**
1. 이벤트마다 색인 작업을 작업 큐에 넣고, 같은 대상의 대기 작업은 하나로 합쳐야 한다.
2. 작업은 DB 에서 지금 상태를 다시 읽어 문서를 넣거나 지워야 한다(이벤트 순서가 뒤바뀌어도 결과가 같다).
3. 일감의 비공개 · 작성자 · 담당 · 프로젝트가 바뀌면 그 일감의 메모 문서도 고쳐야 한다. 프로젝트 상위가 바뀌면 그 아래 문서의 프로젝트 경로를 고쳐야 한다.
4. 쓰고 5초 안에 찾아져야 한다.
5. 다시 만들기는 새 색인을 채운 뒤 별칭을 바꿔 멈춤 없이 해야 한다. 워크스페이스 하나만 다시 채울 수도 있어야 한다.
6. 매일 DB 와 색인의 문서 수를 비교해 다르면 다시 채워야 한다.
7. OpenSearch 가 안 되면 작업을 미뤄 다시 하고, 업무 쓰기는 영향받지 않아야 한다.

**수용 기준**
- [ ] 일감을 만들고 5초 안에 검색된다
- [ ] 같은 일감의 이벤트를 뒤섞어 처리해도 색인 문서가 DB 와 같다
- [ ] 다시 만들기 동안 검색이 계속 된다
- [ ] OpenSearch 를 멈춘 동안 일감 저장이 실패하지 않고, 다시 켜면 밀린 색인이 채워진다

<a id="fr-act-010"></a>
### FR-ACT-010 MCP 로 활동 보기

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §16](../design/08-collaboration.md#co-mcp) |

**설명** — 바깥 Agent 가 "어제 이 프로젝트에 무슨 일이 있었나"(스탠드업 · 요약)를 물을 수 있게 활동을 MCP 도구로 연다.

**세부 요구사항**
1. `get_activity` 는 프로젝트(선택) · 하위 포함 · 사람 · 종류 · 행위자 종류 · 기준 시각 · 개수를 받아 화면과 같은 항목을 돌려줘야 한다.
2. 항목마다 시각 · 종류 · 제목 · 행위자(종류 포함) · 경로 · 주소를 담아야 한다. 제목 · 요약은 "사용자 데이터"로 표시해야 한다.
3. 키 주체의 권한 ∩ 엔드포인트 대상 프로젝트로 걸러야 한다.
4. 개수 상한과 커서가 있어야 한다.

**수용 기준**
- [ ] 같은 사람의 개인 키로 부른 결과가 화면 활동과 같다
- [ ] 엔드포인트 대상이 아닌 프로젝트 활동이 나오지 않는다

<a id="fr-act-011"></a>
### FR-ACT-011 내 페이지 기본 블록

| 항목 | 내용 |
|---|---|
| 우선순위 | M |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §13](../design/08-collaboration.md#co-mypage) |

**설명** — 워크스페이스에 들어오면 "내 담당 일감" · "알림" · "내가 보고한 일감" · "다가오는 버전" 블록이 있는 내 페이지가 보인다. Redmine 내 페이지와 같다.

**세부 요구사항**
1. 기본 배치는 왼쪽 "내 담당 일감" · "알림", 오른쪽 "내가 보고한 일감" · "다가오는 버전"이어야 한다.
2. 블록 데이터는 질의 · 알림 · 버전 API 를 그 블록 조건으로 불러 가져와야 한다(블록 전용 API 를 두지 않는다).
3. 블록마다 보는 사람이 읽을 수 있는 것만 보여야 한다.
4. 390px 에서는 블록이 한 줄로 쌓여야 한다.

**수용 기준**
- [ ] 처음 들어온 사람에게 기본 블록 넷이 보인다
- [ ] "내 담당 일감" 수가 "담당 = 나 · 열림" 질의 결과와 같다
- [ ] 390px 에서 가로 스크롤 없이 보인다

<a id="fr-act-012"></a>
### FR-ACT-012 내 페이지 꾸미기

| 항목 | 내용 |
|---|---|
| 우선순위 | S |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §13](../design/08-collaboration.md#co-mypage) · [§14.2 SQL](../design/08-collaboration.md#co-ddl) |

**설명** — 블록을 더하고 옮기고 닫고, 블록마다 설정을 바꾼다. 저장한 질의 블록은 여러 개 놓는다(Redmine 과 같다).

**세부 요구사항**
1. 블록 목록: 내 담당 · 내가 보고한 · 관찰 중인 일감, 저장한 질의(여러 개), 최근 뉴스, 캘린더, 최근 문서, 소요 시간, 최근 활동, 알림, 다가오는 버전, 내 Agent 활동이어야 한다.
2. 위(전체 폭) · 왼쪽 · 오른쪽 세 칸에 끌어 놓을 수 있어야 한다.
3. 블록 설정(열 · 개수 · 질의 · 일수)을 바꿀 수 있어야 한다.
4. 배치는 사람 × 워크스페이스마다 저장하고 낙관적 잠금을 지켜야 한다.
5. 저장 질의가 지워지거나 볼 수 없게 되면 블록에 "볼 수 없다"와 설정 단추를 보여야 한다.

**수용 기준**
- [ ] 블록을 옮기고 새로 고쳐도 배치가 그대로다
- [ ] 저장 질의 블록 두 개가 각각 다른 질의 결과를 보인다
- [ ] 지운 저장 질의 블록이 오류 대신 "볼 수 없다"를 보인다

<a id="fr-act-013"></a>
### FR-ACT-013 첨부 내용 검색

| 항목 | 내용 |
|---|---|
| 우선순위 | C |
| 진행 | 할 일 |
| 관련 설계 | [공동 작업 설계 §12.1](../design/08-collaboration.md#co-search-targets) · [§18](../design/08-collaboration.md#co-decisions) |

**설명** — 첨부 파일(PDF · 오피스 · 글 파일)의 본문도 검색한다. Redmine 은 첨부 이름 · 설명만 찾는다.

**세부 요구사항**
1. 첨부를 올리면 작업 큐에서 글자를 뽑아 그 첨부가 속한 대상 문서의 첨부 필드에 넣어야 한다.
2. 뽑을 글자 크기 상한을 두고, 실패하면 이름 · 설명만 색인해야 한다.
3. 권한은 첨부가 속한 대상의 규칙을 그대로 따라야 한다.

**수용 기준**
- [ ] PDF 본문 낱말로 그 PDF 가 붙은 일감이 찾아진다
- [ ] 그 일감을 못 읽는 사람에게는 나오지 않는다
