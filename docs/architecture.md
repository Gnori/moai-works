# MOAI Works — 아키텍처 & 기능 맵

> **MOAI Agent 기반 업무 플랫폼** (AI-native Groupware). 작성: 2026-06-03 · 초기 설계.

전통적 그룹웨어(조직/게시판/결재…) 위에 **메신저·메일·파일드라이브·지식관리**를 얹고,
이 모든 것을 **AI Agent 계층**이 가로질러 자동화·지능화하는 구조.

> **AI Agent 계층은 모노레포의 [`moai-agent`](../../moai-agent/) 프레임워크 기반으로 구축**한다
> (moai-echomind 의 Brain/Agent 와 동일 기반). `moai-agent` 는 Python(LangGraph) 이므로,
> 그룹웨어 코어(`moai-works-api`, Spring Boot)와 **별도의 Python AI 서비스**(`moai-works-ai`)로
> 분리하고 REST 로 연동한다.

## 1. 제품 레이어 구조

```
                          ┌──────────────────────────────────────┐
   진입점 (Home)          │  개인 대시보드 · 오늘 일정 · 알림 ·    │
                          │  최근 문서 · 미처리 업무 · AI 업무 브리핑 │
                          └──────────────────────────────────────┘
   ───────────────────────────────────────────────────────────────
   🤖 지능 계층            AI Agent (Main / Sub / 도메인별 Agent)
                          + 예약·자동화 (스케줄·조건 기반 실행)
   ───────────────────────────────────────────────────────────────
   🧠 지식·생산성          지식관리(RAG/Wiki) · AI 문서작성 · AI 온보딩
   ───────────────────────────────────────────────────────────────
   💬 협업·데이터          AI 메신저 · Mail-box · AI 파일드라이브/라이브러리
   ───────────────────────────────────────────────────────────────
   🏢 기반 업무 모듈       조직도·게시판·일정·전자결재·업무관리·문서함·
                          인사/근태·알림·권한관리·감사로그
   ───────────────────────────────────────────────────────────────
   🔌 연계                ERP · 인사 · 회계 · 문서관리 · 업무포털 · MCP · 레거시
```

핵심: **데이터(문서·메시지·메일)** → **지식화(RAG/Wiki)** → **Agent가 활용**해 사용자 업무를 대행/보조.

### 🏗 SaaS 토대 (cross-cutting · 최우선)

본 제품은 **멀티테넌트 SaaS** 로 제공한다. 아래는 기능이 아니라 **모든 모듈을 관통하는 토대**라,
어떤 업무 기능보다 **먼저** 구축한다.

| 축 | 내용 |
|----|------|
| **멀티테넌시** | 테넌트(회사)별 데이터 격리. 모델 선택 필요(아래 결정) |
| **테넌트 부트스트랩** | 회사 가입·생성, 첫 관리자, 도메인/서브도메인 |
| **인증/인가** | 테넌트 범위 인증(SSO/JWT), 테넌트 내 RBAC, **테넌트 경계 강제** |
| **구독/요금(Billing)** | 플랜·시트·사용량 미터링·결제(추후) |
| **운영** | 테넌트별 설정·한도(quota)·감사로그·관측성·온보딩 |

**멀티테넌시 모델 후보** (택1 — 데이터 모델 전반에 영향):

| 모델 | 격리 | 비용/운영 | 비고 |
|------|------|-----------|------|
| **공유 DB + `tenant_id`** (행 단위) | 논리적 | 가장 저렴·단순 | SaaS 초기 표준. 모든 테이블 tenant_id + 강제 필터 |
| 스키마-per-테넌트 | 중간 | 중간 | 테넌트 수 많아지면 운영 부담 |
| DB-per-테넌트 | 물리적 | 비쌈 | 규제/대형 고객용 |

> 권장(초기): **공유 DB + tenant_id** + 모든 쿼리에 테넌트 필터 강제(인터셉터/RLS). 추후 대형
> 고객만 분리 가능.

## 3. AI Agent 아키텍처

```
                ┌─────────────┐
   사용자 요청 ─▶│  Main Agent  │  의도 파악 · 라우팅 · 오케스트레이션
                └──────┬──────┘
                       │ 위임
        ┌──────────────┼───────────────┬───────────────┐
   ┌────▼────┐   ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
   │지식 Agent│   │문서작성 Agent│   │ 일정 Agent │   │전자결재Agent│  …
   └─────────┘   └───────────┘   └───────────┘   └───────────┘
   온보딩 · 이메일 · 메신저 · 예약작업 · 레거시 처리 Agent + Sub Agent(작업 분할)
```

| Agent | 책임 |
|-------|------|
| **Main Agent** | 사용자 의도 분류 → 적절한 도메인 Agent로 라우팅·오케스트레이션 |
| **Sub Agent** | 복합 작업을 하위 단계로 분할 실행 |
| 지식 Agent | RAG/Wiki 질의응답, 출처 기반 답변 |
| 문서작성 Agent | 템플릿·지식 기반 문서 생성/내보내기 |
| 이메일 / 메신저 Agent | 메일·대화 요약·초안·액션아이템 추출 |
| 일정 / 전자결재 Agent | 일정 조율·예약, 결재 문서 초안·흐름 |
| 온보딩 Agent | 신규자 안내·문서 추천·진행률 |
| 예약 작업 Agent | 스케줄·조건 기반 자동 실행 |
| 레거시 시스템 처리 Agent | 외부/레거시 연동 (ERP·인사·회계·MCP) |

> **구현 기반**: 위 Agent 들은 모두 [`moai-agent`](../../moai-agent/) 프레임워크로 구축
> (Main/Sub Agent 오케스트레이션 · Tool 호출 · LangGraph). moai-echomind 의
> Agent/Brain/Tool 패턴을 그대로 재사용 가능 (예: 도메인별 LangChain Tool 바인딩).

## 4. 기술 구성 (제안)

**2개 백엔드 + 1 프런트**: 그룹웨어 코어(Spring Boot)와 AI 계층(Python·moai-agent)을 분리.

```
[ React 19 + TS (moai-works-web) ]
        │ REST / WebSocket(메신저·알림)
        ▼
[ Spring Boot (moai-works-api) ]  ◀── 그룹웨어 코어 (도메인·트랜잭션·권한)
   ├─ 도메인: user/auth/org/board/calendar/approval/task/file/hr/notify/audit
   ├─ 연계: ERP·인사·회계·MCP·레거시 커넥터
   └─ AI 요청 위임 ──REST──▶ ┐
                              │
[ Python AI 서비스 (moai-works-ai) ]  ◀── moai-agent 기반 AI 계층
   ├─ Main/Sub Agent · 도메인 Agent (지식·문서작성·메신저·일정·결재·온보딩…)
   ├─ 지능형 RAG / LLM Wiki / 문서 지식화 / OCR·문서분석
   └─ 예약·자동화 (스케줄·조건 기반 Agent 실행)
        │
[ DB(PostgreSQL) · 벡터DB(RAG) · 오브젝트스토리지(파일) · 캐시(Redis) · LLM ]
```

| 컴포넌트 | 스택 | 책임 |
|----------|------|------|
| `moai-works-web` | React 19 + TS + Vite | 대시보드·메신저·문서 UI (REST + WebSocket) |
| `moai-works-api` | **Spring Boot** (Java/Kotlin) | 그룹웨어 도메인·권한·트랜잭션·외부연계 |
| `moai-works-ai` | **Python + [moai-agent](../../moai-agent/)** | AI Agent·RAG·문서작성·지식화·자동화 |

- **연동**: web ↔ api(REST/WS). api ↔ ai(내부 REST). ai 는 moai-agent 로 Agent/Tool 실행.
- **저장소**: 관계형 DB(업무) + 오브젝트 스토리지(문서) + 벡터 DB(지식) + Redis(캐시·실시간).
- **참고**: 이 api↔ai 분리는 moai-echomind 의 패턴과 유사 (echomind 는 FastAPI 였고, 여기선
  코어가 Spring Boot 인 점만 다름).

## 5. 단계별 로드맵 (제안)

| 단계 | 범위 | 비고 |
|------|------|------|
| **P0 기반** | 조직/사용자·인증·권한 · 게시판 · 알림 · 파일드라이브(저장/권한) | 그룹웨어 코어 |

| **P3 Agent** | Main/Sub Agent · 도메인 Agent(지식·문서작성·메신저·일정) | 지능화 |
| **P4 생산성** | AI 문서작성 · 전자결재 초안 · AI 온보딩 | 업무 대행 |
| **P5 자동화·연계** | 예약/조건 기반 자동화 · ERP·인사·회계·MCP·레거시 연계 | 확장 |

> 각 단계는 `/dev req <name> --scale=complex` 로 요구사항 명세화 후 진행 권장.

## 6. 기술 결정

### ✅ 확정 (2026-06-03)

| 항목 | 결정 |
|------|------|
| **멀티테넌시** | **공유 DB + `tenant_id`** (행 단위 논리 격리). 모든 테이블 `tenant_id` + 쿼리 강제 테넌트 필터(인터셉터/RLS). 추후 대형 고객만 분리 가능 |
| **인증/IAM** | **Keycloak** (자체 IdP 미구축) — OIDC·OAuth2·**SAML**·**LDAP/AD** 페더레이션을 Keycloak이 처리. 앱은 OAuth2 Resource Server(토큰 검증) + OIDC 클라이언트. 멀티테넌시 = Keycloak **Organizations**(또는 realm-per-tenant) |
| **백엔드 언어** | **Java** (Spring Boot) |
| **벡터 DB** | **Qdrant** — 지식관리(F7) RAG (기존 `moai-vectorDB` 컨테이너 재사용) |
| **문서/오피스 (F8·F4)** | **OnlyOffice Document Server** — 기존 OOXML(.docx/.xlsx/.pptx) **고충실 열기/편집** + 신규작성 + 협업 + 내보내기(Office/PDF). AI 작성 = Document Builder(서버 생성) + 플러그인/Automation(에디터 삽입). **별도 컴포넌트(서비스)** |
| **문서 파싱/지식화** | **Apache POI** (Java, `moai-works-api`) — 업로드 OOXML 파싱·내용추출 → 미리보기·OCR·F7 RAG 인덱싱 (편집기와 독립) |

### 🐳 기존 Docker 인프라 활용 (재사용)

신규 구축 대신 **이미 떠 있는 모노레포 인프라를 재사용**한다 (별도 database/스키마/버킷으로 분리).

| 컨테이너 | 이미지/포트 | moai-works 용도 |
|----------|-------------|-----------------|
| `MOAI-DB` | postgres :5432 | 앱 DB(`moai_works`) + **Keycloak DB(`keycloak`)** |
| `moai-vectorDB` | Qdrant :6333 | F7 지식관리 RAG 벡터검색 (컬렉션 분리) |
| `MOAI-Redis` | redis :6379 | 캐시·세션·메신저 실시간 pub/sub (DB index 분리) |
| `MOAI-MinIO` | MinIO :9000 | F4 파일드라이브·F8 문서 오브젝트 스토리지 (버킷 분리) |
| `MOAI-Neo4j` | neo4j :7687 | (옵션) 조직/지식 그래프 |
| Prometheus/Grafana/Jaeger | 9090/3100/16686 | 관측성 재사용 |
| **Keycloak** (신규) | quay.io/keycloak :8080 | **IAM — 신규 컨테이너 추가**, DB는 `MOAI-DB` 재사용 |

> 멀티테넌트 격리는 **공유 DB + tenant_id**(F0-01)와 **버킷/컬렉션/Redis-index 네임스페이싱**을 함께 적용.
