# 핵심 설계 결정 (ADR)

<a id="adr-001"></a>
## ADR-001 그룹웨어를 접고 프로젝트 관리 시스템으로 피봇한다

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21 사용자 지시: "이 프로젝트를 레드마인 같은 프로젝트 관리 시스템으로 전면 정리") |
| 맥락 | 2026-06 에 "AI-native 그룹웨어"(조직 · 결재 · 근태 · 메신저 · 메일 · 파일 · 지식 + 내장 AI)를 명세만 143개 썼고 코드는 없었다. 범위가 너무 넓었다 |
| 결정 | Redmine 의 기능(프로젝트 · 일감 · 워크플로 · 버전 · 간트 · 시간 · 위키 · 알림 · 저장소 · REST)을 기준으로 한 프로젝트 관리 시스템을 만든다. 옛 명세는 지운다(git 이력 `5ba3a92` 에 남는다) |
| 결과 | 요구사항 · 설계를 새로 썼다([요구사항](../requirements/00-overview.md)). 그룹웨어 기능은 범위 밖이다([개요 §3](../01-overview.md#3-범위)) |

<a id="adr-002"></a>
## ADR-002 토대를 moai-wiki 와 같게 하고 코드를 가져온다

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21 사용자 지시: "moai-works-web-backend, moai-works-web-frontend 이렇게 만들고 moai-wiki 디렉토리 구조로 가자. src 아래로 모듈들 넣고 디펜던시도 같게, 인증도 같게, 역할 권한도, 워크스페이스도") |
| 맥락 | moai-wiki 에는 계정 · 가입 · 워크스페이스 · 역할 · 멤버십 · 초대 · 감사 · MCP 키 · BFF 로그인 · React 뼈대가 이미 동작하고 테스트가 있다 |
| 결정 | 저장소 모양(`src/` 아래 모듈 · `infra/` · `tools/` · 규칙 문서 · `docs/` 구성), 의존성 판, 인증(Keycloak Organizations · BFF 세션 · JWT 직접 검증 · MCP 키), 역할과 권한(권한 코드 = 클라이언트 역할 · 접근 어노테이션 · 권한 상승 방지), 워크스페이스(개인/팀 · 퍼블릭/프라이빗 · 가입 신청 · 초대)를 그대로 쓴다. moai-wiki 의 api · web-backend · web-frontend 를 복사해 이름을 바꾸고 위키 · 페이지 · 자료실을 걷어 냈다 |
| 결과 | 첫날부터 로그인 · 워크스페이스 · 권한이 돈다(api 테스트 66건, 화면 테스트 60건). 대신 토대를 고칠 때 두 저장소를 함께 볼 일이 생긴다([DEVELOPE.md](../../DEVELOPE.md) 의 형제 저장소 줄). 공통 라이브러리로 뺄지는 나중에 본다 |

<a id="adr-003"></a>
## ADR-003 AI Agent 를 내장하지 않는다 — 바깥 Agent 가 MCP 로 붙는다

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21 사용자 지시: "AI Agent 자체는 내장할 계획은 없고, AI Agent 가 프로젝트 관리할 수 있고 MCP 로 그걸 연결할 수 있게" · "moai-works-ai 는 제거") |
| 맥락 | 피봇 전 설계에는 Python AI 서비스(`moai-works-ai`)가 있었다. 요약 · 분류 같은 기능은 모델이 빠르게 바뀌고, 쓰는 사람마다 원하는 Agent 가 다르다 |
| 결정 | 시스템 안에 LLM · Agent 를 두지 않는다. api 가 **MCP 서버**가 되어 프로젝트 · 일감 · 계획 · 시간 · 위키를 도구로 연다. Agent 는 사람의 개인 키나 Agent 계정의 서비스 키로 붙는다 |
| 결과 | `moai-works-ai` 를 지웠다. 모듈은 셋(api · web-backend · web-frontend). AI 기능은 "MCP 도구가 충분한가"로 바뀐다([FR-MCP](../requirements/12-mcp.md) · [MCP 설계](07-mcp-agents.md)) |

<a id="adr-004"></a>
## ADR-004 판정은 api 한 곳, MCP 도구는 REST 와 같은 서비스를 부른다

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (moai-wiki 와 같은 원칙) |
| 결정 | 권한 판정은 api 에만 있다. REST 핸들러는 접근 어노테이션 정확히 하나(없으면 기동 실패). MCP 도구는 서비스 메서드를 부르는 얇은 층이고, 모델이 넘긴 프로젝트 · 일감도 주체의 권한으로 다시 판정한다. 화면 · BFF 는 판정하지 않는다 |
| 결과 | 웹과 MCP 가 같은 결과를 낸다는 "동등성"을 테스트로 지킨다([테스트 전략](../plan/02-test-strategy.md)) |

<a id="adr-005"></a>
## ADR-005 권한 경계는 프로젝트, 프로젝트 역할은 고정 4종

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 맥락 | moai-wiki 는 "위키 = 권한 경계"이고 위키 역할 4종(관리자 · 큐레이터 · 편집자 · 독자)을 Keycloak 조직 그룹으로 둔다. Redmine 은 프로젝트 멤버십에 역할(관리자 · 개발자 · 보고자)을 준다 |
| 결정 | 프로젝트를 권한 경계로 삼는다(공개 범위 `WORKSPACE` · `RESTRICTED`, 독자가 아니면 404). 프로젝트 역할은 관리자 · 개발자 · 보고자 · 독자 네 가지로 고정해 시작한다. 사용자 정의 프로젝트 역할은 나중(C) |
| 결과 | 판정 규칙은 moai-wiki 의 위키 층과 같은 꼴이 된다([프로젝트 권한 설계](04-project-permissions.md)) |

<a id="adr-006"></a>
## ADR-006 프로젝트 역할 바인딩의 정본은 Keycloak 조직 그룹

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | 사람의 프로젝트 역할은 Keycloak 조직 그룹 `/projects/<project id>/<role key>` 가 정본이고 api DB `project_role_binding` 은 판정용 사본이다(moai-wiki 의 위키 역할과 같다). Agent 계정은 Keycloak 에 없으므로 사본 표의 주체 종류(`AGENT`)로 api DB 가 정본이다 |
| 위험 | 프로젝트 수 × 역할 수만큼 조직 그룹이 생긴다 → 규모 시험에서 확인한다([정해야 할 것](../wbs/08-decisions.md)) |

<a id="adr-007"></a>
## ADR-007 AI Agent 는 "Agent 계정"으로 일한다

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 맥락 | moai-wiki 의 서비스 키는 "워크스페이스 명의"였다. 프로젝트 관리에서는 Agent 가 일감 담당자가 되고, 누가 무엇을 했는지 사람과 구분해 보여야 한다 |
| 결정 | 워크스페이스에 사람 아닌 멤버 "Agent 계정"을 둔다. 이름 · 책임자(사람) · 상태를 가지고, 프로젝트 역할을 받고, 일감 작성자 · 담당자 · 관찰자가 될 수 있다. 로그인은 못 하고 서비스 키로만 일한다. 개인 키로 붙은 Agent 는 그 사람으로 기록하되 "MCP 로" 경로를 남긴다 |
| 결과 | [MCP 설계](07-mcp-agents.md) · [FR-MCP](../requirements/12-mcp.md) |

<a id="adr-008"></a>
## ADR-008 MCP 인증은 엔드포인트에 묶인 MCP 키

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | moai-wiki 와 같은 MCP 키(Bearer, SHA-256 만 저장, 요청마다 캐시 없이 검사)를 쓴다. 키는 엔드포인트 하나에 묶인다. MCP 권한 부여 사양(OAuth 2.1)은 클라이언트 지원이 넓어지면 더한다(C) |
| 결과 | 지금 코드의 고정 입구 `/mcp/project` 를 워크스페이스 엔드포인트 `/mcp/{ws}/{ep}` 로 옮긴다([WBS 3단계](../wbs/04-stage-3-mcp.md)) |

<a id="adr-009"></a>
## ADR-009 일감 번호는 워크스페이스 안 순번

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | Redmine 처럼 프로젝트와 상관없는 하나의 순번 `#123` 을 쓰되, 범위는 워크스페이스다. 프로젝트를 옮겨도 번호는 그대로다. 프로젝트 접두사(`ABC-12`)는 쓰지 않는다 |
| 결과 | 글 속 `#123` 링크와 커밋 키워드가 단순하다. Redmine 이관 때 번호 대응표가 필요하다 |

<a id="adr-010"></a>
## ADR-010 본문은 Markdown(GFM) 하나

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | 일감 설명 · 메모 · 위키 · 뉴스 등 모든 본문은 Markdown(GFM). 편집기는 moai-wiki 와 같은 CodeMirror 6 + 미리보기. Redmine 의 Textile 은 이관 때 변환한다 |

<a id="adr-011"></a>
## ADR-011 사용자 정의 필드 값은 JSONB

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | 정의는 `custom_field` 표, 값은 엔티티의 `custom_values` JSONB 열 + GIN 색인. Redmine 의 EAV(`custom_values` 표) 대신 PostgreSQL 의 JSONB 로 필터 · 정렬을 한다 |
| 위험 | 형식 검증을 api 가 맡아야 한다. 정렬이 많은 필드는 생성 열 · 식 색인을 더한다 |

<a id="adr-012"></a>
## ADR-012 전문 검색은 OpenSearch(nori)

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | moai-wiki 와 같은 OpenSearch 3.9(한국어 형태소 nori)를 쓴다. 색인은 `moai-works-*`. 권한 조건은 api 가 계산해 질의에 넣는다. 일감 필터 · 목록은 PostgreSQL 이 한다 |

<a id="adr-013"></a>
## ADR-013 뒷일은 api 안 DB 작업 큐

| 항목 | 내용 |
|---|---|
| 상태 | 제안 |
| 결정 | 메일 보내기 · 웹훅 전달 · 검색 색인 · 가져오기는 업무 트랜잭션 안에서 작업(아웃박스)으로 쌓고, api 안의 스케줄러가 가져가 처리한다(재시도 · 실패 기록). 워커 모듈을 따로 두지 않는다 |
| 결과 | 모듈이 셋으로 유지된다. 처리량이 커지면 같은 큐를 읽는 워커로 나눌 수 있다 |

<a id="adr-014"></a>
## ADR-014 같이 쓰는 컨테이너 · 포트 1100x · 렐름 moai-works

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21) |
| 결정 | 로컬은 MOAI-DB(DB `moai_works`) · MOAI-Redis(`moai-works:`) · MOAI-MinIO(`moai-works-attachments`) · MOAI-OpenSearch(`moai-works-*`) · MOAI-Keycloak(렐름 `moai-works`)를 쓴다. 포트는 api 11001 · web-backend 11002 · web-frontend 개발 서버 11003 — 처음에는 moai-wiki(1000x)와 끝자리를 맞춘 1001x 였으나 같은 날 사람이 1100x 로 다시 정했다. moai-wiki 와 겹치지 않는다 |

<a id="adr-015"></a>
## ADR-015 토대 스키마를 V1 하나로

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21) |
| 결정 | moai-wiki 의 V1 ~ V3 · V8 · V9 가 만든 토대 표의 최종 모양을 `V1__foundation.sql` 하나로 옮겼다(위키 · 페이지 · 자료실 표는 없다). moai-works DB 는 새로 만들었으므로 옮겨 갈 데이터가 없다. 이후 변경은 V2 부터 새 파일로 |

<a id="adr-016"></a>
## ADR-016 워크스페이스 기본 역할은 셋

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-11-21, 구현) |
| 결정 | moai-wiki 의 기본 역할 넷 가운데 `curator`(위키 내용 담당)를 뺐다. owner(전부) · admin(소유자 전용 빼고 전부) · member(보기 · 개인 MCP 키). 프로젝트 안에서 할 수 있는 일은 프로젝트 역할이 정한다([ADR-005](#adr-005)). 프로젝트 · 일감 권한 코드는 그 기능을 만들 때 카탈로그에 더한다 |
