# 정해야 할 것

작업을 막거나 방향을 바꾸는 결정이다. 이 쪽에는 **사람이 정해야 하는 큰 것**만 모은다. 각 줄의 "제안"은 설계 쪽이 기본으로 적어 둔 답이다 — 이견이 없으면 그대로 진행한다. 그래서 지금 작업을 멈추게 하는 결정은 없다.

정해지면 `상태` 에 날짜와 답을 적고, 설계를 바꾸는 결정이면 [ADR](../design/00-key-decisions.md)도 남긴다.

> **2026-11-22 다시 정리하며 바꾼 것:** 목록을 새로 짰다. 전날의 결정 가운데 "Agent 계정"(권한 상한 · 자기 시간 기록 · 시트 · REST)과 Redmine 기능(보고자의 시간 기록)에 걸린 것은 범위에서 빠져 지웠다. 멤버의 프로젝트 만들기(주지 않음) · 프로젝트 역할의 정본(Keycloak 조직 그룹) · 공개 프로젝트의 역할 없는 멤버(워크스페이스 역할만으로 판정)는 "moai-wiki 와 같게"로 답이 정해져 닫았다([ADR-005](../design/00-key-decisions.md#adr-005) · [ADR-006](../design/00-key-decisions.md#adr-006)). 남은 결정은 아래 D-06 ~ D-09 로 옮겼다.

## 2. 결정마다 자세히

### D-01 큐레이터 이름

| 선택지 | 장단점 |
|---|---|
| **그대로 "큐레이터"** | moai-wiki 와 이름 · key · 권한 모양이 같아 두 저장소의 코드 · 문서 · Keycloak 그룹을 같은 말로 다룬다. 프로젝트 관리 도구에서는 낯선 말이다 |
| "편집자" · "기여자" 등으로 바꿈 | 뜻은 더 잘 들어온다. moai-wiki 와 이름이 갈라져 토대를 고칠 때마다 옮겨 적어야 한다 |

**제안: 그대로.** 화면 이름(리소스의 말)만 바꾸는 것은 나중에도 된다 — key `curator` 는 두 저장소에서 같게 둔다.

### D-02 다른 프로젝트와의 연결 일감

| 선택지 | 장단점 |
|---|---|
| **같은 프로젝트 안만** | 판정이 간단하다 — 연결을 보는 사람은 이미 그 프로젝트의 독자다. 두 일감의 권한이 늘 같다 |
| 다른 프로젝트도 | 실제로는 자주 필요하다. 상대 일감의 독자가 아니면 연결을 어떻게 보일지(숨김 · "볼 수 없는 일감")와 MCP 범위를 정해야 한다 |

**제안: 같은 프로젝트 안만**으로 시작하고, 다른 프로젝트는 나중 후보로 둔다. 표(`issue_link`)는 프로젝트 열 없이 두 일감 id 만 가지므로 나중에 넓혀도 옮길 데이터가 없다.

**결정 (2026-11-24, 사람):** 일감을 워크스페이스 아래로 옮기면서(사용자: "레드마인을 생각하면 돼" — [ADR-030](../design/00-key-decisions.md#adr-030)) 같은 워크스페이스의 다른 프로젝트 일감과도 잇는다. 대상은 거는 사람이 읽을 수 있는 일감이어야 하고(아니면 없는 번호와 같은 400), 보는 사람이 읽을 수 없는 프로젝트의 상대는 보기에서 빠진다(있다는 것도 숨긴다). 다른 프로젝트 상대의 제목은 알림에 싣지 않는다. 데이터는 옮길 것이 없었다([3.9](04-stage-3-issue.md#w-3-9)).

### D-03 상태 · 일감 유형을 프로젝트마다

**제안: 고정.** 상태 넷(신규 · 진행 · 완료 · 종료)은 날짜 자동 채움([ADR-020](../design/00-key-decisions.md#adr-020))과 묶여 있고, 유형 넷(요구사항 · 기능 · 버그 · 작업)은 moai-wiki 의 페이지 유형처럼 공통 시드 표다. 프로젝트마다 바꾸기는 사용자 정의 워크플로와 함께 나중 후보로 둔다.

### D-04 관리자 · 담당자를 여러 명

**제안: 각각 한 명.** 관리자는 moai-wiki 의 페이지 소유자 자리(한 명)이고, 담당자를 여럿 두면 목록 필터 · 알림 · MCP 도구의 인자가 모두 목록이 된다. 여러 사람이 함께 하는 일은 하위 일감으로 나눈다.

### D-05 나중 후보의 순서

**제안: 첨부 → 관찰자 · 알림 → 활동 → 전문 검색.** 첨부는 버킷 · 저장소 코드가 이미 있어 가장 싸고, 알림은 사람이 일감을 따라가는 데 가장 먼저 필요하다. 활동은 이력 · 감사를 모아 보이기만 하면 되고, 전문 검색은 일감이 쌓인 뒤에 값이 난다. 버전 · 로드맵 · 시간 기록 같은 계획 기능이 먼저 필요하면 이 순서를 바꾼다.

## 3. 설계 쪽의 자세한 질문

설계 쪽마다 "정해야 할 것"이 있고, 질문마다 그 쪽이 기본으로 고른 답이 적혀 있다. 그 기본대로 만들고, 바꾸려면 그 쪽과 이 쪽을 함께 고친다: [프로젝트 설계](../design/04-project.md) · [일감 설계](../design/05-issue.md) · [MCP 설계](../design/06-mcp.md).
