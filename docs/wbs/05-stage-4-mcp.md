# 4단계 — MCP

바깥 AI Agent(Claude Code 등)가 MCP 로 붙어 프로젝트 · 일감을 찾고 · 읽고 · 만들고 · 고치고 · 댓글을 단다. moai-wiki 의 MCP 체계와 같다 — 사용자 계정에 묶인 MCP 키(SHA-256 만 저장, 주인의 권한 안에서만 일한다), 워크스페이스 MCP 엔드포인트 `/mcp/{ws}/{ep}`, 도구는 REST 와 **같은 서비스 · 같은 판정**을 부르고 호출마다 다시 판정한다. 엔드포인트의 대상이 위키 대신 프로젝트라는 것과 서비스 키 · 서비스 읽기 방식이 없다는 것([ADR-024](../design/00-key-decisions.md#adr-024))이 다르다. 이 제품의 이유라 일감 서비스가 서자마자 한다([ADR-003](../design/00-key-decisions.md#adr-003) · [ADR-008](../design/00-key-decisions.md#adr-008)).

설계: [MCP 설계](../design/06-mcp.md) · [SECURITY.md](../../SECURITY.md) §5.2 · §8.3.

**완료 기준:** 워크스페이스 관리자가 AGENT 엔드포인트(대상 프로젝트 하나 · 쓰기 도구 켬)를 만들고, 멤버가 그 엔드포인트의 자기 MCP 키를 받는다. Claude Code 를 붙여 [UC-05 · UC-06](../01-overview.md#6-핵심-시나리오)을 시연한다 — Agent 가 담당 일감을 찾아 읽고, 댓글을 달고, 상태를 바꾸고, 하위 일감을 만든다. 이력에는 "그 사람 (MCP 로)"가 남는다. 웹과 MCP 의 동등성 · 범위 · 키 · 재판정 테스트가 돈다.

## 이 단계에서 뺀 것

- **"Agent 계정"**(사람 아닌 멤버로 Agent 를 두는 안)은 없앴다 — moai-wiki 에 없는 것이다([ADR-007](../design/00-key-decisions.md#adr-007) 폐기).
- **서비스 키 · 엔드포인트의 서비스 읽기 방식**(워크스페이스 이름으로 사람 권한을 넘어 일하는 키)은 없앴다 — MCP 키는 사용자 계정에 묶이고 그 사람의 권한 안에서만 일한다(2026-11-22 사용자 결정, [ADR-024](../design/00-key-decisions.md#adr-024)).
- 시간 · 버전 · 위키 · 활동 도구, 리소스 · 프롬프트, OAuth 2.1 은 그 기능이 없거나 나중 후보다.
