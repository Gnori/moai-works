# 2단계 — 프로젝트

**다음 순서다.** moai-wiki 의 위키 자리에 프로젝트를 만든다. 워크스페이스 안에 프로젝트가 여러 개 있고, 프로젝트가 **권한 경계**다(독자가 아니면 404). 만들기 · 설정 · 보관 · 복원 · 삭제 · 공개 범위 · 프로젝트 역할까지 moai-wiki 의 `wiki/` 코드와 `features/wiki` 화면을 본떠 만든다. 일감이 들어올 틀(`ProjectLayout`)도 이 단계에서 선다.

설계: [프로젝트 설계](../design/04-project.md) · [워크스페이스·계정·권한](../design/03-workspace-identity.md)(기본 역할 넷 · 권한 코드 25개). 결정: [ADR-005](../design/00-key-decisions.md#adr-005)(권한 경계 = 프로젝트, 프로젝트 역할 고정 넷) · [ADR-006](../design/00-key-decisions.md#adr-006)(프로젝트 역할의 정본 = Keycloak 그룹) · [ADR-017](../design/00-key-decisions.md#adr-017)(기본 역할 넷).

**완료 기준:** 워크스페이스 A 소유자가 프로젝트를 만들면 멤버 모두에게 보인다. 멤버에게는 만들기 단추가 없고, API 로 직접 부르면 403 이다. `RESTRICTED` 프로젝트는 프로젝트 역할이 없는 멤버에게 404 이고, 프로젝트 역할을 주면 다음 요청부터 보인다. 보관한 프로젝트는 목록의 보관 탭으로 가고, key 를 입력해야 지워진다. 개인 워크스페이스에는 "내 프로젝트"가 있다. 그 프로젝트의 `project-admin` 은 역할을 주고 빼되 자기 권한 밖의 역할은 못 준다.

묶음마다 api → 화면 → 브라우저 확인 순서로 끝까지 만들고 커밋한다.

## 이 단계에서 뺀 것

전날 명세의 2단계에 있던 하위 프로젝트 · 모듈 켜고 끄기 · 트래커 · 워크플로 · 우선순위 · 사용자 정의 필드 · 첨부 · 질의 엔진은 moai-wiki 에 없는 것이라 [나중 후보](../01-overview.md#32-나중-후보)로 옮겼다. 일감은 [3단계](04-stage-3-issue.md)에서 만든다.
