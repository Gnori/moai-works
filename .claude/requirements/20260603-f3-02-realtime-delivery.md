## 1. 요구사항 분석
### 1.1 문제 정의
알림은 **즉시** 사용자 화면에 떠야 한다. WebSocket 연결 + **Redis pub/sub**으로 다중 인스턴스
환경에서도 실시간 전달한다. (메신저 F5 도 동일 토대 재사용)
### 1.2 목표
- WebSocket(STOMP) 허브 — JWT 인증(F0-03) 후 연결
- **Redis pub/sub** 으로 인스턴스 간 팬아웃 → 해당 사용자 세션에 push
- 연결 관리(핑/재연결)·온라인 상태 · 격리(테넌트/사용자)

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | WS 엔드포인트(JWT 인증·구독) | Must |
| F-002 | Redis pub/sub 브로커(인스턴스 간) | Must |
| F-003 | 사용자 세션 라우팅·연결관리 | Must |
| F-004 | 미수신(오프라인) → 저장만(F3-01)·후속 채널(F3-03) | Should |

## 3. 기능 설계
### 3.1 아키텍처
```
알림 발행 → Redis publish(채널: notif:user:{id}) 
WS 인스턴스들 subscribe → 연결된 사용자 세션에 push
오프라인 → 저장(F3-01) + 푸시/메일(F3-03)
```
### 3.2 스택
Spring WebSocket(STOMP) · Redis(MOAI-Redis, DB index 분리) · JWT 핸드셰이크
