## 1. 요구사항 분석
### 1.1 문제 정의
바쁜 사용자는 **수십~수백 개의 채널 메시지**를 모두 읽기 어렵다. 자리를 비운 사이 쌓인 대화,
긴 토론 스레드의 핵심을 빠르게 파악하고 **놓친 결정·중요 메시지**를 추출할 필요가 있다.
### 1.2 목표
- **대화 요약**(기간/스레드 단위) · **안 읽은 메시지 요약**(F5-04 읽음 기준) · **중요 메시지 추출**
- F13 Agent 호출(F7 지식 컨텍스트 결합) · **F13 미완 시 fallback**(추출 요약) · 격리·권한·감사

## 3. 기능 설계
### 3.1 데이터 모델
- `message_summary(id, tenant_id, channel_id, thread_id?, scope=channel/thread/unread, range_from, range_to, message_count, summary_text, key_points jsonb, important_message_ids bigint[], engine=agent/fallback, requested_by, created_at)`
- `important_message_flag(id, tenant_id, message_id, summary_id, reason=decision/request/deadline/mention, score)`
- 요약은 **온디맨드 생성** + 단기 캐시(동일 범위·30분 내 재사용). 모든 행 `tenant_id`(F0-01 RLS).

### 3.2 흐름
1. 사용자 "요약" 요청 → 범위 결정(unread는 F5-04 워터마크, 그 외 기간/메시지수)
2. 채널 **읽기 권한 검증**(F0-07) → 범위 내 메시지 수집(격리 필터)
3. **F13 Agent 호출**: 메시지 + F7 지식 컨텍스트 → 요약·핵심·중요메시지 분류
4. 결과 저장(`message_summary`) → 요약 카드 응답(근거 메시지 deep-link 포함)
5. 감사 로그(F0-08): 요청자·범위·엔진 기록

### 3.3 F13/F7 미완 fallback (MANDATORY)
- **F13 미완**: `engine=fallback`. 추출형 요약 — 키워드 빈도·발화자 분포·멘션/기한 키워드 매칭으로 상위 N개 메시지를 "중요"로 선별, 요약문은 템플릿(`{기간}·{N}건·주요 발화자·핵심 키워드`)으로 구성.
- **F7 미완**: 지식 컨텍스트 없이 메시지 본문만으로 처리. 컨텍스트 보강은 F7 완성 후 연계.
- placeholder 응답에 `"ai_engine": "fallback"` 플래그 명시 → 클라이언트 배지 표시.

### 3.4 API
| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/v1/channels/{id}/summary` | 대화 요약(body: scope, range) |
| GET | `/api/v1/channels/{id}/summary/unread` | 안 읽은 메시지 요약 |
| GET | `/api/v1/threads/{id}/summary` | 스레드 요약 |
| GET | `/api/v1/channels/{id}/important` | 중요 메시지 추출 목록 |
| POST | `/api/v1/summaries/{id}/regenerate` | 요약 재생성 |
