## 1. 요구사항 분석
### 1.1 문제 정의
회사 조직은 **부서 계층(트리)**로 구성된다. 부서 생성·이동·통폐합·정렬을 관리하고, 다른
모듈(권한·결재선·공유)이 부서 트리를 참조한다.
### 1.2 목표
- 부서 **계층 CRUD**(상위/하위) · 순서 · **이동(서브트리)** · 통폐합·비활성
- 트리 조회(전체/부분) · 순환 방지 · 격리(F0-01)

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 부서 CRUD(name, parent, order, status) | Must |
| F-002 | 서브트리 이동(부모 변경) + 순환 방지 | Must |
| F-003 | 통폐합/비활성(소속 이동 처리) | Should |
| F-004 | 트리 조회(전체/부분·경로) | Must |

## 3. 기능 설계
### 3.1 데이터 모델
`departments(id, tenant_id, parent_id, name, sort_order, status, path)` — `path`(materialized path) 또는 closure table 로 트리 조회 최적화
### 3.2 API
`POST/PATCH/DELETE /departments` · `PATCH /departments/{id}/move` · `GET /departments/tree`
- 관리 권한(F0-07 `org:manage`), 조회는 멤버
