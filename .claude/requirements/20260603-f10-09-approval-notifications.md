## 1. 요구사항 분석
### 1.1 문제 정의
결재 흐름의 각 전환(상신·결재요청·반려·완료)은 **당사자에게 즉시 통지**되어야 하고,
**미결재 건이 방치되지 않도록** 결재자에게 지연 리마인드를 보내야 한다. 알림 생성·전달은
직접 구현하지 않고 **F3 알림**에 위임하며, 지연 점검은 **F14 스케줄**로 주기 실행한다.
### 1.2 목표
- 결재 이벤트별 알림 트리거(상신→결재자, 반려/완료→기안자) → F3 발행
- **지연(SLA 초과) 미결재 리마인드** — 스케줄 기반 점검 후 결재자에게 재통지
- 수신 대상 결정(현재 결재자·기안자·상위자)은 F1-06 조직/상위자 조회 결합
- 테넌트 격리 · 발송 이력 감사(F0-08)

### 2.1 기능 상세
#### F-001 이벤트 알림
- 결재 상태 전환 시 이벤트 수신 → F3 `notify(template, recipients, payload)` 호출
- 매핑: 상신/결재요청 → **다음 결재자**, 반려 → **기안자**, 완료 → **기안자**(+옵션 참조자)
- 템플릿 키: `approval.submitted` · `approval.requested` · `approval.rejected` · `approval.completed` · `approval.reminder`
#### F-002 지연 리마인드
- 문서별 **SLA(결재 대기 허용시간)** 초과 미결재 건을 **F14 스케줄**(예: 1h 주기)로 점검
- 초과 건 → 현재 결재자에게 `approval.reminder` 재발행 · **재알림 간격·최대 횟수** 제한
- 에스컬레이션(옵션): 임계 초과 시 **상위자**(F1-06) 동시 통지
#### F-003 수신 대상
- 현재 결재 단계의 결재자 = 결재선에서 산출 · 기안자 = 문서 소유자
- 상위자·부서장 조회는 **F1-06** 결합(직접 조직 조회 금지)

## 3. 기능 설계
### 3.1 데이터 모델
- `approval_sla(tenant_id, document_id, due_at, level)` — 대기 단계별 마감
- `approval_reminder_log(tenant_id, document_id, recipient_id, kind, sent_at)` — 중복/횟수 제어·감사
- 알림 본문/채널 상태는 **F3 소유**(여기선 저장 안 함)
### 3.2 흐름
```
[이벤트] 상태전환(상신/반려/완료)
  → ApprovalNotifier: 수신대상(F1-06) 산출 → F3.notify(template, recipients)
[스케줄] F14 cron(1h)
  → 미결재 SLA 초과 조회(tenant 격리)
  → reminder_log 검사(간격·최대횟수) → 미초과 시 F3.notify(reminder)
  → 임계 초과 시 상위자(F1-06) 에스컬레이션
  (모든 조회 F0-01 테넌트 격리 · 발송 F0-08 감사)
```
### 3.3 API / 권한
- 내부 이벤트 핸들러 중심(공개 API 최소). 정책 조회/설정 시 `@RequiresPermission`
  - `GET /approval/notifications/policy` — `approval:read`
  - `PUT /approval/notifications/policy` — `approval:manage`
- 모든 엔드포인트 기본 deny(F0-07) · 타 테넌트 문서 접근 차단
