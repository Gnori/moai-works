## 1. 요구사항 분석
### 1.1 문제 정의
테넌트 **관리자(OWNER/ADMIN)**가 워크스페이스를 운영할 **기본 관리 콘솔**이 필요하다:
설정(브랜딩·인증방식), 사용자·역할 관리, 구독·사용량, 감사로그 조회.

### 1.2 목표
- 테넌트 **설정**(이름·브랜딩·기본 인증방식·정책)
- 사용자/역할·구독/사용량·감사로그 **관리 화면 토대**(API + 기본 UI)
- 모두 **ADMIN 권한**(F0-07)·테넌트 격리(F0-01)

### 1.3 제약
- 신규 도메인 로직 최소 — 기존 F0-01~09 기능을 **집약·노출**하는 관리 레이어
- 플랫폼 운영자 콘솔(전 테넌트)과는 구분(본 spec 은 테넌트 admin)

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 테넌트 설정(브랜딩·인증방식·정책) | Must |
| F-002 | 사용자/역할 관리 화면(F0-06·07) | Must |
| F-003 | 구독·사용량 보기(F0-09) | Must |
| F-004 | 감사로그 조회(F0-08) | Must |
| F-005 | 관리 진입 권한·메뉴(ADMIN) | Must |

### 2.2 상세
- **F-001**: `tenant_settings`(브랜딩·기본 IdP·비번정책 등) CRUD
- 화면은 기존 모듈 API 집약(신규 비즈로직 최소)

## 3. 기능 설계
### 3.1 스택
Spring Boot(API) · React(moai-works-web 관리 영역) · PostgreSQL
### 3.2 흐름
```
ADMIN 로그인 → /admin/* (RBAC: tenant:admin)
 ├─ 설정(tenant_settings)
 ├─ 사용자/역할(F0-06/07)
 ├─ 구독/사용량(F0-09)
 └─ 감사로그(F0-08)
```
### 3.3 데이터 모델
`tenant_settings(tenant_id PK, branding jsonb, default_auth, policies jsonb)` + 기존 토대 재사용
