## 1. 요구사항 분석
### 1.1 문제 정의
인사 체계는 **직급(grade, 서열)**과 **직책(position, 역할)**으로 나뉜다. 결재선(전결 권한)·
호칭·정렬에 쓰이므로 표준 체계가 필요하다.
### 1.2 목표
- 직급(사원~임원 등 **서열 rank**) · 직책(팀장·부서장 등) 정의·CRUD
- 결재/권한이 참조할 **서열 비교** 가능 · 테넌트별 커스텀

## 2. 기능 정의

|----|------|---------|

## 3. 기능 설계
### 3.1 데이터 모델
`grades(id, tenant_id, name, rank)` · `positions(id, tenant_id, name, is_manager)`
### 3.2 API
`/grades`, `/positions` CRUD (org:manage). 서열 비교 `GradeService.isHigher(a,b)`
