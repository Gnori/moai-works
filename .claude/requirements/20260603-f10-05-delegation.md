## 1. 요구사항 분석
### 1.1 문제 정의
결재 담당자가 **부재**(휴가·출장·외근)일 때 결재가 멈추면 업무가 정체된다. 부재 기간 동안
타인에게 결재 권한을 **위임(delegation)** 하거나, 담당자 대신 처리하는 **대결(代決)** 을 허용하고,
도착하는 결재를 자동으로 **대리자에게 라우팅**해야 한다. 모든 위임·대결 행위는 추적 가능해야 한다.
### 1.2 목표
- **위임 설정**(위임자→대리자, 기간, 범위) · 기간 만료 시 자동 해제
- 결재 도착 시 활성 위임 평가 → **자동 대리 라우팅**(F10 본 흐름 결합)
- **대결 처리**: 대리자가 결재 시 "OOO 대결" 명시 + 원 담당자/상위자 통보
- 위임 이력·대결 이력 **감사**(F0-08) · 테넌트 격리

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 위임 설정 CRUD(대리자·기간·범위) | Must |
| F-002 | 활성 위임 평가 + 자동 대리 라우팅 | Must |
| F-003 | 대결 처리(대리 결재 + "대결" 표기) | Must |
| F-004 | 기간 만료/취소 시 자동 해제 + 알림(F3) | Should |
| F-005 | 위임/대결 이력 조회 + 감사(F0-08) | Should |

### 2.2 기능 상세
#### F-001: 위임 설정
- `위임자`가 `대리자`(같은 테넌트 멤버, F1-06 조직 조회로 선택)·`기간(시작~종료)`·`범위`(전체 / 특정 결재유형·문서종류) 지정
- 자기 자신·순환 위임 금지 검증 · 기간 중복 위임 충돌 검증(409)
- 위임 설정/수정/취소는 `approval:delegate` 권한 필요(F0-07)

#### F-002: 자동 대리 라우팅
- 결재 도착 시(F10 본 흐름) 현재 결재선 담당자에 **활성 위임**이 있으면 대리자를 실제 결재 가능자로 추가
- 평가 기준: `now ∈ [시작,종료]` · 범위 매칭 · 미취소 · 대리자 재직(F1-06)
- 원 담당자도 직접 처리 가능(위임은 권한 부여이지 박탈 아님)

#### F-003: 대결 처리
- 대리자가 결재 시 결재 결과에 `대결자 = 대리자, 원담당자 = 위임자` 기록 · 화면 "OOO 대결" 표기
- 대결 완료 시 원 담당자에게 통보(F3) · 결재선 진행은 본 흐름과 동일

#### F-004: 해제/알림
- 종료일 경과 또는 명시적 취소 시 위임 비활성 · 위임자·대리자에게 알림(F3)
- 활성화/만료 임박(D-1) 알림(F3, Should)

#### F-005: 이력/감사
- 위임 설정·변경·취소, 대결 발생을 F0-08 감사로그 기록(actor, 위임자, 대리자, 범위, 기간)
- 위임 이력·대결 건 조회 API(관리자/본인)

## 3. 기능 설계
### 3.1 기술 스택
Spring Boot · Spring Security(`@RequiresPermission`) · PostgreSQL+RLS · Flyway · JUnit5
### 3.2 데이터 모델
- `approval_delegation(id, tenant_id, delegator_id, delegate_id, scope_type=all/type, scope_value, starts_at, ends_at, status=active/cancelled/expired, created_at)`
  - 인덱스 `(tenant_id, delegator_id, status, starts_at, ends_at)`
- `approval_delegation_log(id, tenant_id, delegation_id, action, actor_id, at)` — F0-08 연계
- 대결 흔적은 결재 결과(`approval_action`)에 `proxy_for_id`(원 담당자) 컬럼 추가
- 모든 테이블 `tenant_id` + RLS(F0-01) · 교차 테넌트 차단
### 3.3 흐름 / API
```
결재 도착 → 담당자 위임 평가(F-002)
  → 활성 위임 有 ? 대리자 결재 가능자 추가
대리자 결재(F-003) → proxy_for_id=위임자 기록 → "대결" 표기 → 원담당자 알림(F3)
설정/취소(F-001/004) → 감사(F0-08) + 알림(F3)
```
- `POST/PUT/DELETE /api/approval/delegations` — 위임 설정/수정/취소(`approval:delegate`)
- `GET /api/approval/delegations` — 내 위임/받은 위임 조회
- `GET /api/approval/delegations/logs` — 위임/대결 이력(관리자·본인)
- 모든 응답 테넌트 범위 · 기본 deny(F0-07)
