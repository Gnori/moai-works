## 1. 요구사항 분석
### 1.1 문제 정의
새 회사(테넌트)가 **가입 → 워크스페이스 생성 → 첫 관리자(OWNER) 계정 → 도메인/서브도메인
매핑**까지 자가 부트스트랩할 수 있어야 한다. 이게 SaaS 온보딩의 입구다.

### 1.2 목표
- 셀프 가입(또는 운영자 프로비저닝)으로 테넌트 생성
- 첫 사용자 = **OWNER 역할** 자동 부여 · 기본 역할/권한 시드(F0-07)
- 테넌트 **slug/서브도메인** 발급(인증·격리의 테넌트 식별 입력)
- 기본 플랜(F0-09) 배정

### 1.3 제약
- F0-01 격리 위에서 생성(부트스트랩만 테넌트-less 진입점) · slug 전역 unique · 멱등

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 테넌트 생성(회사명·slug/서브도메인) | Must |
| F-002 | 첫 관리자(OWNER) 계정 + 자격 생성 | Must |
| F-003 | 기본 역할/권한 시드(F0-07) · 기본 플랜(F0-09) | Must |
| F-004 | 가입 흐름(셀프/운영자) + 이메일 확인 | Should |
| F-005 | slug/도메인 검증·중복·예약어 처리 | Must |

### 2.2 상세
- **F-001/002 원자성**: 테넌트+OWNER+시드를 단일 트랜잭션으로(부분 생성 방지)
- **F-005**: slug 정규식·예약어(admin/api 등)·중복 → 409

## 3. 기능 설계
### 3.1 스택
Spring Boot · JPA · Flyway · (메일 확인) · PostgreSQL
### 3.2 흐름
```
POST /signup {company, slug, admin{email,pw}} (테넌트-less 진입점)
 → [TX] Tenant 생성 → OWNER User+Credential → 역할/권한 시드 → 기본 플랜
 → (옵션) 이메일 확인 → 활성화 → 첫 로그인
```
### 3.3 데이터 모델
`tenants`(F0-01) 사용 + `tenant_provisioning_log`. users/credentials(F0-03·06).
