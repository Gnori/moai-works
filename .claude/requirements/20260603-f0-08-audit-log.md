## 1. 요구사항 분석
### 1.1 문제 정의
SaaS·엔터프라이즈는 **누가·언제·무엇을 했는지** 추적(보안·규정·분쟁 대응)이 필수다.
인증·권한·중요 행위를 **불변(append-only)** 감사로그로 남기고 테넌트별 조회한다.

### 1.2 목표
- 표준 **감사 이벤트 모델**(actor·action·target·결과·시각·IP/UA)
- 전 모듈이 쉽게 기록하는 **공통 API/애너테이션**
- **불변 보존**(수정/삭제 불가) · 테넌트별 조회·필터·내보내기
- 비동기 기록(성능 영향 최소)

### 1.3 제약
- 테넌트 격리(F0-01) · PII 최소·민감정보 마스킹 · 보존기간 정책

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 감사 이벤트 모델 + 저장(append-only) | Must |
| F-002 | 공통 기록 API/애너테이션(`@Audited`) | Must |
| F-003 | 인증·권한·중요행위 자동 기록 훅 | Must |
| F-004 | 조회·필터·페이지·내보내기(관리자) | Must |
| F-005 | 비동기 기록 + 유실 방지 | Should |

### 2.2 상세
- **F-001**: `audit_logs(id, tenant_id, actor_id, action, target_type, target_id, result, ip, ua, at, meta jsonb)` — UPDATE/DELETE 금지(권한·트리거)
- **F-002**: `@Audited("approval:approve")` 또는 `AuditService.record(...)`
- **F-003**: 로그인 성공/실패·권한거부·역할변경 등 토대 이벤트 자동

## 3. 기능 설계
### 3.1 스택
Spring Boot · 이벤트(ApplicationEvent)/비동기 · PostgreSQL(append-only) · Flyway
### 3.2 흐름
```
행위 → @Audited/AuditService.record → (async) audit_logs insert
조회 → GET /audit?filter (관리자 권한·테넌트 격리)
```
### 3.3 데이터 모델
`audit_logs`(상기) + 보존정책(파티셔닝/아카이브 후속)
