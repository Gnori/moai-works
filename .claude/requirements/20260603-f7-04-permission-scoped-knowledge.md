## 1. 요구사항 분석
### 1.1 문제 정의
지식 RAG 의 최대 리스크 = **권한 없는 문서가 답변에 누출**되는 것. 지식은 **전사/부서/프로젝트/
개인** 범위가 있고, **검색은 사용자가 접근 가능한 지식만** 대상으로 해야 한다.
### 1.2 목표
- 지식 **스코프**(전사/부서/프로젝트/개인) + 소스 문서 권한(F4-03) 상속
- 벡터 검색 시 **권한 필터 강제**(Qdrant 메타 필터: scope·부서·acl)
- 사용자 권한(F0-07)·소속(F1) 으로 검색 범위 산출 · **누출 0**

### 1.3 제약
- 권한 변경/소속 변경 → 검색 범위 즉시 반영 · 기본 deny · 격리(F0-01)

## 2. 기능 정의
| ID | 기능 | 우선순위 |

## 2.2 상세
- **F-003**: RAG 검색(F7-02) 쿼리에 **반드시** 권한 필터(`tenant_id == X AND (scope=전사 OR dept∈사용자부서 OR acl∋사용자)`) 결합. 필터 없는 검색 금지.
- **F-004**: 사용자 부서(F1)·역할(F0-07) → 접근 가능 scope/dept 집합 계산.

## 3. 기능 설계
### 3.1 흐름
```
인덱싱 시: 청크 메타 = scope + dept + acl(소스 F4-03 상속)
검색 시: 사용자 접근범위(F0-07/F1) → Qdrant 필터 결합 → 접근 가능 지식만 검색
```
