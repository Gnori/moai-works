## 1. 요구사항 분석
### 1.1 문제 정의
기안자가 결재 문서를 **작성·임시저장·첨부**하고, **결재선을 적용**해 **상신**하는 진입점이 필요하다.
상신 시 결재 흐름(F10-04)이 시작되고 **첫 결재자에게 알림**이 가야 한다. AI 결재초안(F8) 작성 보조를
선택적으로 연계한다.

### 1.2 목표
- 기안 작성(양식·본문·첨부 F4 재사용) · **임시저장(draft)** · 결재선 적용 · **상신(submit)**
- 상신 시 문서 상태 전이(draft→submitted) · 첫 결재자 알림(F3) · 감사(F0-08)
- **AI 결재초안(F8)** 연계 훅 — 본문 초안 생성(선택)
- 모든 엔티티 `tenant_id` 격리 · `@RequiresPermission` 권한

## 3. 기능 설계
### 3.1 기술 스택
Spring Boot · Spring AOP(`@RequiresPermission`) · PostgreSQL+RLS · Flyway · JUnit5 · F3 알림 클라이언트 · F8 AI 훅(비동기)

### 3.2 데이터 모델
- `approval_document(id, tenant_id, drafter_id, form_id, title, body, status, submitted_at, created_at)` — status=draft/submitted/in_progress/...
- `approval_doc_attachment(id, tenant_id, document_id, file_id)` — F4 `file_id` 참조(복사 아님)
- `approval_line_step(id, tenant_id, document_id, seq, approver_id, type=approve/agree/ref, status)` — 상신 시 결재선 스냅샷
- 인덱스: `(tenant_id, drafter_id, status)` · `(tenant_id, document_id, seq)` · RLS 정책 tenant_id

### 3.3 핵심 흐름 / API
```
[작성] POST /api/approval/documents               @RequiresPermission("approval:submit")
        → draft 생성(또는 AI 훅 F8로 body 초안)
[수정] PUT  /api/approval/documents/{id}           draft 만 수정 가능 · 본인/격리
[첨부] POST /api/approval/documents/{id}/attachments  body: {fileId}  (F4 권한 검증)
[결재선] PUT /api/approval/documents/{id}/line     직접 지정 또는 templateId(F10-02) 전개
        approver_id 검증 = F1-06 조직/상위자 조회
[상신] POST /api/approval/documents/{id}/submit
        → 상태 draft→submitted, 결재선 스냅샷 확정, F10-04 흐름 개시
        → 첫 결재자에게 F3 알림(approval.submitted)
        → F0-08 감사 기록
[회수] POST /api/approval/documents/{id}/recall    첫 결재 전만 · submitted→draft
[AI훅] POST /api/approval/documents/{id}/ai-draft  F8 호출 → body 제안(반영은 사용자 확정)
```
- 상신 검증: 제목/본문 필수 · 결재선 ≥1단계 · 모든 approver 동일 테넌트 · draft 상태에서만
- 격리: 모든 조회/수정에 tenant_id 강제(RLS) · 첨부 file_id 도 동일 테넌트 검증
