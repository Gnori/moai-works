## 1. 요구사항 분석
### 1.1 문제 정의
온프레미스 기업은 **LDAP/AD 디렉터리**로 사용자·인증을 관리한다. 이를 앱에서 직접 붙이지
않고 **Keycloak User Federation** 으로 연동한다 — Keycloak이 LDAP 바인드 인증·사용자/그룹
동기화를 담당하고, 앱은 F0-03 의 동일 토큰 경로만 본다.

### 1.2 목표
- **테넌트(Organization)별 LDAP/AD 페더레이션**(Keycloak) — host·baseDN·bind·LDAPS
- LDAP 자격으로 로그인 → Keycloak 토큰(F0-03)
- 사용자/그룹 **동기화**(주기/온디맨드) → 앱 사용자(F0-06) + **부서(F1 조직)** 입력

### 1.3 제약
- Keycloak LDAP federation provider 사용 · 시크릿 Keycloak 보관 · LDAPS 권장
- 동기화 결과를 앱 F0-06/F1 에 반영하는 매핑·웹훅/스케줄

## 3. 기능 설계
### 3.1 스택
Keycloak LDAP User Federation · (앱은 F0-03 경로) · 동기화 매핑(이벤트/스케줄, F14 연계 가능)
### 3.2 흐름
```
로그인 → 앱 → Keycloak → LDAP bind(자격검증) → Keycloak 토큰 → 앱(F0-03)
동기화 → Keycloak ↔ LDAP(users/groups) → (이벤트/스케줄) → 앱 F0-06·F1 반영
```
### 3.3 설정/모델
- Keycloak: Organization 별 LDAP provider + group/attribute mapper (IaC)
- 앱: `user_identities`(provider=ldap) 매핑 · 부서는 F1 조직 모델
