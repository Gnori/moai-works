## 1. 요구사항 분석
### 1.1 문제 정의
SaaS 는 테넌트별 **플랜·시트(사용자 수)·사용량 한도(quota)**를 관리하고 초과를 통제해야 한다.
(실제 **결제 연동은 추후**, 본 spec 은 플랜·한도·미터링 토대)

### 1.2 목표
- 플랜 정의(기능/한도 묶음) · 테넌트 구독 배정
- **시트 한도**(F0-06 초대 시 체크) · **사용량 미터링**(스토리지·AI 호출 등)
- 한도 초과 시 **차단/경고** · 사용량 조회

### 1.3 제약
- 격리(F0-01) · 결제 게이트웨이는 후속(인터페이스만) · 한도 평가 성능

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 플랜 카탈로그(기능·한도) | Must |
| F-002 | 테넌트 구독(플랜 배정·상태) | Must |
| F-003 | 시트 한도 평가(F0-06 연동) | Must |
| F-004 | 사용량 미터링(스토리지·AI·문서 등) | Should |
| F-005 | 한도 초과 차단/경고 + 사용량 조회 | Must |

### 2.2 상세
- **F-001**: 플랜 = 기능 플래그 + 한도(seats, storageGB, ai_calls/월 …)
- **F-003**: 멤버 초대 시 `usedSeats < plan.seats` 체크 → 초과 시 거부
- **F-004**: 사용량 카운터(usage_records) — 모듈이 기록(F4 저장·F13 AI 호출 등)

## 3. 기능 설계
### 3.1 스택
Spring Boot · JPA · PostgreSQL · (결제 인터페이스 stub)
### 3.2 데이터 모델
`plans(id, name, features jsonb, limits jsonb)` · `subscriptions(tenant_id, plan_id, status, period)` · `usage_records(tenant_id, metric, amount, period)` · `usage_counters`(집계)
### 3.3 흐름
```
초대/업로드/AI호출 → QuotaService.check(metric) → 허용/차단
사용 발생 → UsageService.record(metric, amount)
```
