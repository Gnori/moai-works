## 1. 요구사항 분석
### 1.1 문제 정의
휴가는 **신청→결재→반영**의 일관 흐름이 필요하다. 휴가 신청은 별도 화면이 아니라
**F10 결재 양식**(F10-07)으로 처리하고, 승인 시 **잔여 차감**(F12-03)·**근태 반영**(F12-02)·
**캘린더/조직 표시**가 자동 연동되어야 한다. 반려·취소 시 부수효과를 정확히 되돌린다.
### 1.2 목표
- 휴가 신청 = **결재 양식**(휴가종류·기간·반차·사유) · 결재선 = F1-06 상위자
- 승인 시 → 잔여 차감 + 근태 반영 + 캘린더/조직 노출 + 신청자 알림(F3)
- 반려/취소 → 차감 복원·근태/캘린더 철회 · 모든 처리 격리·감사(F0-08)

## 3. 기능 설계
### 3.1 데이터 모델
- `leave_requests(id, tenant_id, applicant_id, leave_type, start_at, end_at, half_day, days, reason, approval_doc_id, status=draft/pending/approved/rejected/cancelled, created_at)`
- `approval_doc_id` → F10 결재 문서(상태 동기화) · 인덱스 `(tenant_id, applicant_id, status)`·`(tenant_id, start_at)`
- 모든 행 **tenant_id 격리**(F0-01) · 교차 테넌트 접근 차단
### 3.2 흐름/API
```
신청: POST /leave/requests → 잔여 사전검증(F12-03) → F10 결재 양식(F10-07) 생성, 결재선=F1-06 상위자 → status=pending
승인: F10 승인 콜백 → 잔여 차감(F12-03) + 근태 반영(F12-02) + 캘린더/조직 표시 + 알림(F3) → status=approved
반려: F10 반려 콜백 → 차감 미발생, 신청자 알림 → status=rejected
취소: DELETE /leave/requests/{id} → (승인 후) 차감 복원·근태/캘린더 철회 → status=cancelled
```
- `GET /leave/requests`(본인/관리 범위) · 권한 = F0-07 `@RequiresPermission`(`leave:apply`/`leave:manage`)
- 부수효과(차감·근태·캘린더)는 **트랜잭션/멱등** 처리 · 결재 상태와 leave 상태 정합 보장
