## 1. 요구사항 분석
### 1.1 문제 정의
게시판은 **종류(공지/부서/프로젝트/자유)**와 **가시성·작성권 범위**(전사/부서/역할)가 다르다.
관리자가 게시판을 만들고 범위를 지정한다.
### 1.2 목표
- 게시판 CRUD(type·name·설명) · **가시성/작성권 범위**(전사·부서·역할) 설정
- 공지 게시판(전사 읽기·관리자 작성) 등 프리셋 · 격리/권한

## 2. 기능 정의
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 게시판 CRUD(type, name) | Must |
| F-002 | 가시성/작성권 범위(부서·역할) | Must |

## 3. 기능 설계
### 3.1 데이터 모델
`boards(id, tenant_id, type, name, read_scope, write_scope, settings jsonb, status)` — scope = 전사 / 부서(ids) / 역할(keys)
### 3.2 API
`/boards` CRUD(`board:manage`) · `GET /boards`(가시성 필터)
