## 1. 요구사항 분석
### 1.1 문제 정의
결재는 **유형마다 입력 항목·검증·후처리**가 다르다. 기안서/휴가신청/지출결의/구매요청/출장신청/품의서/인사발령
**7종 표준 양식**을 정의하고, 휴가신청은 F12-03 연차 잔여와 연동, 승인 완료 시 각 양식의 **후처리**(HR/회계/업무 반영)를 F10-10 으로 트리거한다.
### 1.2 목표
- 양식별 **스키마**(필드·필수·검증) + 결재선 기본값 매핑(F10 마스터)
- **휴가신청 ↔ F12-03**: 잔여 연차 조회·검증, 승인 시 차감
- 승인 완료 → 양식별 후처리 이벤트(F10-10) · 알림(F3) · 감사(F0-08) · 테넌트 격리

### 2.2 양식별 상세
- **기안서**: 제목·본문·첨부 → 일반 업무 결재(후처리 없음, 보관)
- **휴가신청**: 휴가유형(연차/반차/병가)·기간·사유 → 잔여 검증(F12-03), 승인 시 **차감**
- **지출결의**: 비용항목·금액·증빙 → 승인 시 **회계 반영**(지출 등록)
- **구매요청**: 품목·수량·예상금액·납기 → 승인 시 **구매 요청 생성**
- **출장신청**: 출장지·기간·교통/숙박·예산 → 승인 시 출장 등록(정산 연계)
- **품의서**: 안건·예산·승인요청 → 승인 시 의사결정 확정 보관
- **인사발령**: 대상자·발령유형(승진/이동/직책)·발효일 → 승인 시 **HR 반영**(조직 변경, F1)

## 3. 기능 설계
### 3.1 데이터 모델
- `form_types(id, tenant_id, code, name, schema_json, default_line_policy, post_action)` — 7종 시드
- `approval_forms(id, tenant_id, approval_id, form_type_code, payload_json)` — 기안 인스턴스
- `post_process_log(id, tenant_id, approval_id, form_type_code, action, status, ref_id)`
- 모든 테이블 `tenant_id` (F0-01) · 인덱스 `(tenant_id, form_type_code)`

### 3.2 흐름
```
기안 작성 → form_types.schema 검증 → (휴가) F12-03 잔여 조회·검증
  → 결재선 결정(F1-06 상위자/담당) → 결재 진행(F10)
  → 최종 승인 → 양식별 post_action 이벤트(F10-10)
       휴가→F12-03 차감 / 지출→회계 / 구매→구매요청 / 인사발령→HR(F1)
  → 알림(F3 신청자·관련자) + 감사(F0-08)
```
### 3.3 API
| 메서드 | 경로 | 권한 | 설명 |
|--------|------|------|------|
| GET | `/api/approval/form-types` | `approval:read` | 양식 목록·스키마 |
| GET | `/api/approval/form-types/{code}` | `approval:read` | 단일 양식 스키마 |
| POST | `/api/approval/forms` | `approval:submit` | 양식 기반 기안 작성(검증) |
| GET | `/api/approval/forms/{id}` | `approval:read` | 기안 양식 조회 |
- `@RequiresPermission` 강제 · 기본 deny · 휴가 잔여 초과 시 **400**, 타 테넌트 자원 **404/격리**
