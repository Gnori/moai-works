## 1. 요구사항 분석
### 1.1 문제 정의
전 모듈(게시판·결재·일정·발령…)이 **단일 발행 API** 로 알림을 보내야 한다. 디스패처가
**대상 resolve(조직 팬아웃) → 사용자 설정 평가 → 채널 라우팅 → 발송**을 담당한다.
### 1.2 목표
- 공통 `NotificationService.publish(event, targets, channels)`
- 대상 resolve: 사용자 / **부서·역할 팬아웃**(F1-06) / 구독자
- 사용자 설정(F3-03) 평가 → 채널(웹 F3-02·푸시·메일) 라우팅 · 비동기·재시도

## 3. 기능 설계
### 3.1 흐름
```
모듈 → publish(event, targets, channels)
 → 대상 resolve(F1-06: 부서/역할 → 사용자 집합)
 → 각 사용자: 설정(F3-03) 평가 → 저장(F3-01) + 채널(웹 F3-02·푸시·메일)
 → (비동기 큐·재시도·dedupe)
```
### 3.2 설계
이벤트 카탈로그(type) · 멱등키(중복 알림 방지) · 큐(비동기)
