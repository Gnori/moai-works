## 1. 요구사항 분석 및 상세화

### 1.1 문제 정의
모든 업무 모듈(게시판·결재·파일…)은 **"누가 무엇을 할 수 있나"** 통제가 필요하다. 본 spec 은
**테넌트 범위 RBAC**(역할·권한 모델 + 강제 메커니즘)를 토대로 만든다. 각 모듈은
`@RequiresPermission` 만 붙이면 접근제어가 적용된다.

### 1.2 목표
- **권한 카탈로그**(`module:action` 키, 예 `board:write`, `approval:approve`)
- **역할(테넌트 범위) ↔ 권한** 매핑, **사용자 ↔ 역할** 할당(테넌트 멤버십 내)
- **`@RequiresPermission` 강제** — 기본 deny, 권한 없으면 403
- 시스템 **기본 역할 시드**(OWNER/ADMIN/MEMBER) + 권한 평가(JWT roles → permissions)

### 1.3 제약 조건
- Java + Spring Boot(AOP/Security) · PostgreSQL · F0-01 테넌트 격리 위에
- **기본 deny** · 최소 권한 · 권한 변경은 감사로그(F0-08) 대상

## 2. 기능 정의

### 2.1 핵심 기능 목록
| ID | 기능 | 우선순위 |
|----|------|---------|
| F-001 | 권한 카탈로그(`module:action`) 정의·등록 | Must |
| F-002 | 역할(테넌트 범위) + 역할-권한 매핑 | Must |
| F-003 | 사용자-역할 할당(멤버십 범위) | Must |
| F-004 | `@RequiresPermission` 강제(AOP/Security) + 기본 deny | Must |
| F-005 | 시스템 기본 역할 시드 + 권한 평가/캐시 | Must |

### 2.2 기능 상세

#### F-001: 권한 카탈로그
- 권한 키 = `module:action` (예: `board:read/write/delete`, `approval:submit/approve`, `file:share`)
- 모듈이 자기 권한을 **선언적으로 등록**(enum/레지스트리) → 카탈로그 집계
- 권한은 **전역 정의**(코드 소유), 역할 매핑은 테넌트별

#### F-002·F-003: 역할/할당
- `Role`(tenant 범위, name, 설명) ↔ `Permission` 다대다(`role_permissions`)
- `User` ↔ `Role` 다대다(`user_roles`, 테넌트 멤버십 범위) — 한 사용자 다중 역할 가능
- 역할/할당 CRUD API(관리자 권한 필요)

#### F-004: 강제
- `@RequiresPermission("board:write")` 메서드 애너테이션 → AOP 인터셉터가 현재 주체의
  유효권한 집합과 대조 → 없으면 **403**, 인증 자체 없으면 401
- **기본 deny**: 권한 미선언 보호 자원은 접근 불가 원칙
- 자원 소유/스코프 체크(부서/프로젝트 범위)는 호출 측 결합(권한 + 스코프)

#### F-005: 평가/시드
- 로그인 시 사용자의 역할 → 권한 집합 산출, JWT `roles` + 서버측 권한 평가(캐시)
- 시드: `OWNER`(전권) · `ADMIN`(관리) · `MEMBER`(기본) — 테넌트 부트스트랩(F0-02) 시 생성
- 권한 변경 즉시 반영(캐시 무효화)

## 3. 기능 설계

### 3.1 기술 스택
Spring Boot · Spring Security(권한 평가) · Spring AOP(`@RequiresPermission`) · PostgreSQL · Flyway · JUnit5

### 3.2 아키텍처 설계
```
요청(인증됨) → @RequiresPermission("x:y") 메서드
  → PermissionInterceptor: 주체 roles → 유효 permission 집합(캐시) 조회
  → 포함? 진행 : 403
  (모든 데이터는 F0-01 테넌트 격리 위에서 조회)
```

### 3.3 데이터 모델
- `permissions(key PK, module, action, description)` — 코드 시드
- `roles(id, tenant_id, name, is_system)` · `role_permissions(role_id, permission_key)`
- `user_roles(user_id, role_id, tenant_id)`
- 인덱스: `(tenant_id, ...)` · 권한 평가용 조인 최적화

### 3.4 핵심 산출물 (재사용 토대)
`Permission`(레지스트리) · `@RequiresPermission` · `PermissionInterceptor` ·
`PermissionEvaluator`/캐시 · 기본 역할 시더 → **F1+ 모듈이 권한 선언만으로 사용**
