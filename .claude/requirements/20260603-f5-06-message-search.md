## 1. 요구사항 분석
### 1.1 문제 정의
누적된 채널 메시지에서 **원하는 대화를 빠르게** 찾아야 한다. 채널 내부/전체 검색,
작성자·기간·채널 **필터**, 그리고 사용자가 **접근 가능한 채널 범위로 제한**된 결과가 필요하다.
### 1.2 목표
- 전체/채널 단위 **키워드 검색**(한국어 형태소 + 부분일치) · **필터**(작성자·기간·채널·첨부유무)
- **권한 범위 제한**(멤버 채널만) · 결과 **하이라이트**·페이지네이션
- 메시지 인덱싱(작성/수정/삭제 동기화) · 격리

## 3. 기능 설계
### 3.1 데이터 모델
- **검색 인덱스**: PostgreSQL `tsvector`(GIN) 우선. `message_search(message_id, tenant_id, channel_id, sender_id, content_tsv, created_at, has_attachment)`
- 한국어: `pg_bigm` 또는 형태소(mecab) 사용 — 미가용 시 `simple` + `LIKE` 부분일치 **fallback**
- 인덱싱: 메시지 INSERT/UPDATE/DELETE 트리거 또는 비동기 워커로 `content_tsv` 동기화
- **시맨틱(F-007)**: Qdrant 컬렉션 — F7(지식) 임베딩 파이프라인 미완 시 **placeholder**(키워드 검색만 노출)

### 3.2 검색 흐름
1. 요청 수신 → 사용자 **멤버 채널 목록** 조회(F5-01)
2. 필터(작성자/기간/채널/첨부) + 키워드 → 쿼리 빌드, **channel_id IN (멤버채널)** 강제
3. `tenant_id` 자동 필터(F0-01 RLS) · `ts_headline`으로 하이라이트 스니펫 생성
4. 정렬(관련도/최신) · 커서 페이지네이션 → 결과 반환

### 3.3 API (`/api/v1/messenger/search`)
| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/messages?q=&channelId=&authorId=&from=&to=&hasFile=&cursor=` | 메시지 검색(권한 범위 자동 제한) |
| GET | `/messages/in/{channelId}?q=&cursor=` | 특정 채널 내 검색(멤버 검증) |
| GET | `/files?q=&channelId=` | 첨부/파일명 검색(F5-05) |

- 권한: 멤버 아닌 채널 지정 시 **403**, 미존재 채널 **404**, 잘못된 기간/파라미터 **400**
- 레이트리밋 초과 **429**
